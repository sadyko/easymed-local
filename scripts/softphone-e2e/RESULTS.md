# Телефон в Easy-Med — проверка в настоящем браузере (SOFTPHONE_V1, задача 9)

Прогон 2026-10-29. Chromium из Playwright 1.58.2 (без окна), бандл JsSIP 3.13.9 из
`public/js/vendor`, подставной SIP-сервер `fake-sip.mjs` на том же http-сервере, что и
Easy-Med (`ws://127.0.0.1:<порт>/fake-sip`). Запуск:

```
node scripts/softphone-e2e/run.mjs --out <папка для снимков>
```

Выход 0 — все сценарии прошли. Итог последнего прогона: **10 из 10**, ошибок и
предупреждений в консоли страниц — 0, обращений наружу — 0. Прогон повторён трижды
подряд — без сбоев.

## Как устроено

- Свежая база (удаляется в конце): администратор, оператор с ролью «Регистратура»,
  номером 108 (назначен в карточке) и правом «Позвонить пациенту», линия onlinePBX,
  выдуманная пациентка «Тестова Пациентка» +998 90 111 22 33. Лицензия — своя,
  подписанная тут же (как `server/services/control/licensed-fixture.js`).
- `telephony_webrtc_me` подменён только в процессе проверки: отдаёт адрес реле.
  `fetch` и `https` наружу закрыты; браузер отводит `*.onpbx.ru` на 127.0.0.1.
- Реле — как АТС: REGISTER получает 401, первый INVITE — 407, ответ Digest
  проверяется. Значит, пароль из `telephony_webrtc_me` действительно доходит до JsSIP.
- «Пациент» B и третий звонящий C — отдельная страница с тем же JsSIP (`patient.html`).
- События станции о тех же звонках («звонит», «ответили», «конец», с опозданием)
  кладутся в живую ленту (`telephony/live.js`) — так проверяется, что блок «Звонит»
  станции не вылезает поверх телефона Easy-Med.
- Байты и уровень звука во вкладке оператора берутся из `getStats()`; для этого
  стенд оборачивает `RTCPeerConnection` скриптом Playwright. В программе таких
  крючков нет.

## Звук (прогон, чьи снимки перечислены ниже)

- Оператор: скрытый `audio[data-softphone-remote]` — 1 живая дорожка, играет;
  `bytesReceived` 5345 → 10026 за 1,5 с; энергия звука 0,54 (Chrome считает её только
  у выводимого звука — значит, звук собеседника действительно играет).
- Пациентка B: `bytesReceived` 9954 → 14723 за 1,5 с.
- «Микрофон выкл.»: у B за 2 с — с микрофоном 6293 байт, энергия 0,59; без микрофона
  303 байта, энергия 0; после повторного нажатия энергия снова 0,47.
- Исходящий: у оператора `bytesReceived` 3510 → 7935, энергия 0,35.

## Дефекты

Дефектов в рабочем коде проверка не нашла — исправлять ничего не понадобилось.
Чтобы убедиться, что проверка вообще умеет падать, три поломки вносились в рабочий
код на время и сразу убирались (в коммиты не попали):

- звук собеседника не кладётся в `<audio>` → упал сценарий 1 («дорожек 0»);
- «Микрофон выкл.» только на экране → упал сценарий 1 (энергия у B не упала);
- неверный пароль в JsSIP → упал сценарий 0 (нет «ready»).

После этого в сценарий 3 добавлена проверка звука у оператора: без неё поломка
`<audio>` проходила бы исходящий.

## Замечания для владельца (не сбой, решение за вами)

1. Пилюля в шапке панели говорит «Готов», когда телефон Easy-Med в ошибке или
   «в другой вкладке», а строка ниже — «Телефон не включился» (снимки 15, 16).
2. После перезагрузки страницы или во второй вкладке неотвеченный звонок станции
   последних 15 секунд показывается блоком «Пропущен» с «Перезвонить» (снимки 12, 16):
   «тишина» о звонках телефона Easy-Med живёт только в странице.
3. Перезагрузка или закрытие вкладки не шлёт АТС «выход» (REGISTER с expires=0), а
   выключение переключателем — шлёт (журнал реле). Подставной сервер забывает номер,
   как только закрыт сокет; как поведёт себя onlinePBX — смотреть на живой проверке.
4. Не телефон Easy-Med: при открытой панели на ширине 1280 заголовок раздела в
   верхней строке сжимается до «П.».

## Что проверить только на живой АТС и с гарнитурой

- `wss://` к onlinePBX, сертификат, вызов пароля самой станции.
- Медиа через NAT: `iceServers` пуст, звук идёт на внешний адрес станции.
- Кодеки со станцией; повторный вход в АТС через ~10 минут (прогон идёт полторы минуты).
- Настоящая гарнитура: выбор микрофона и динамика (`setSinkId`), «проверка за
  5 секунд», писк входящего — без окна устройств нет, микрофон поддельный.
- Адрес клиники `http://<адрес ПК>:8000`: микрофон только после
  `EasyMed-ustanovka.cmd`; здесь страница была на 127.0.0.1 (защищённый адрес всегда).
- Настоящие события onlinePBX рядом со звонком в браузере (здесь их клал сам стенд)
  и вид номера звонящего, по которому находится карта.
- Закрыли вкладку — номер в кабинете onlinePBX уходит из «в сети»?
