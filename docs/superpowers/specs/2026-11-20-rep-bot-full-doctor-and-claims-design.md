# Бот медпредставителей: полная анкета врача и заявка на закрепление существующего

Дата: 2026-11-20. Владелец (со снимком бота): «here we need all data in terms of where
doctor work, speciality and others, if there is doctor with the same number it should go to
approvement before adding to medical representative».

## Решения владельца

| Вопрос | Решение |
|---|---|
| Что спрашивает анкета | ФИО, телефон, **специальность из списка клиники**, место работы, район, **тип оплаты** (+ номер карты при «На карту»). Категорию бот не спрашивает |
| Можно ли пропускать | **Нет — всё обязательно**; кнопки «Пропустить» больше нет, «Отмена» есть всегда |
| Врач с этим номером уже есть | **Заявка на закрепление существующего**: второй карточки нет; администратор подтверждает или отклоняет |
| Врач уже закреплён за другим представителем | Подтверждение **переносит** его к заявителю; прежний представитель получает сообщение в боте |

## Анкета (`server/services/rep-bot/flow.js`)

1. **ФИО** — как сейчас (минимум фамилия и имя).
2. **Телефон** — целый узбекский номер, обязателен. Есть внешний врач с этим номером
   (`findSourceWithPhone`) → анкета закрывается и заводится заявка (ниже).
3. **Специальность — только из списка** (`public/js/shared/specialty-list.js`, около 120
   записей; хранится русское название, как у выпадающего списка «Настроек»). Представитель
   пишет часть названия («кард», «тера», можно по-узбекски) — бот отвечает кнопками
   подходящих (до 8). Ничего не нашлось — просит написать иначе. Выбор кнопкой — по
   индексу в списке, не по тексту из кнопки.
4. **Место работы** — текст, до 120 символов, обязательно.
5. **Район** — текст, до 120 символов, обязательно.
6. **Тип оплаты** — кнопки «Наличные» / «На карту» / «Перечислением» (значения
   `cash` / `card` / `transfer`, как в форме «Настроек»). «На карту» → **номер карты**,
   16 цифр (пробелы допускаются), обязателен.
7. **Сводка** со всеми полями и «Сохранить» / «Отмена» — как сейчас. Сохранение пишет
   `payment_type` и `card_number` вместе с остальным.

Старые анкеты в `rep_bot_drafts` с шагом, которого больше нет, сбрасываются в меню.

## Заявка на закрепление

**Таблица** (миграция 293): `rep_bot_claims` — `id`, `referral_source_id` → врач,
`user_id` → представитель-заявитель, `link_id`, `chat_id`, `entered_name` (ФИО, как его
ввёл представитель — только для сведения администратору), `status`
(`pending` | `approved` | `rejected` | `void`), `prev_representative_id` (кто был
закреплён в момент решения), `decided_by`, `decided_at`, `created_at`. Одна открытая
(`pending`) заявка на пару врач+представитель — частичный уникальный индекс.

**Бот.** На шаге «Телефон» при совпадении: заявка заводится (или находится уже открытая),
ответ «Врач с этим номером уже есть в клинике: <ФИО>, № <номер>. Заявка на закрепление
отправлена администратору». Если врач уже закреплён за этим же представителем — «уже
закреплён за вами», заявки нет. То же правило — при «Сохранить» (номер мог занять другой,
пока шла анкета).

**Администратор** — вкладка «Бот представителей», новый список «Заявки на закрепление»
(только открытые): врач (номер, ФИО, телефон), заявитель, текущий представитель врача
(или «не закреплён»), дата; кнопки «Подтвердить» и «Отклонить». Видит и решает тот же,
кто видит вкладку (администратор).

**Подтверждение** — сервер проверяет: заявка открыта; врач существует; заявитель всё ещё
действующий сотрудник с ролью «Медпредставитель». Закрепление — тем же правилом и тем же
путём, что вкладка «Представители» (`referrals_assign_representative` /
его серверная функция), в одной транзакции со сменой статуса. Не прошла проверка —
заявка `void` и понятное сообщение администратору.

**Сообщения в боте** (best-effort, сбой отправки решения не отменяет):
заявителю — «Врач № … закреплён за вами» или «Заявка на врача № … отклонена»;
прежнему представителю (если был другой и у него есть подключённый чат) — «Врач № …
передан другому представителю».

Данные карточки существующего врача заявка не меняет.

## Проверки

Анкета: обязательность каждого шага, поиск специальности и выбор кнопкой, тип оплаты и
номер карты, сохранение всех полей. Заявка: совпадение номера заводит одну заявку
(повтор — та же), «уже за вами» — без заявки; подтверждение закрепляет и переносит,
отклонение — нет; уволенный заявитель → `void`; сообщения заявителю и прежнему
представителю; права (не администратор — отказ); лицензия (просроченная клиника не пишет).
