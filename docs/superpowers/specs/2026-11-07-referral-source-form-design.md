# Карточка источника направления: порядок полей, выплата, особые ставки по услугам

Дата: 2026-11-07. Владелец (2026-11-07): «Make it more accurate and attractive… no need
to put number as it should be generated by itself… Sequence: Surname, Name, Middle Name,
phone, speciality, region, place of work, type of payment (cash — no card number, card —
card number), category (not internal employee)… give me possibility to provide more % for
some services».

## Что меняется

### 1. Окно «Новый источник направления» / «Источник направления № 0012»

Форма — общий редактор справочников `settings-hub.js` (конфиг `LOOKUP_CONFIG.referral_sources`),
тот же экран открывает вкладка CRM «Врачи-источники» (`referrals-sources.js`). Меняется конфиг
и редактор получает две небольшие общие возможности: разделы и условную обязательность.

Разделы (новое поле конфига `groups`, рисуется существующими стилями `.mg-section` / `.mg-grid`):

| Раздел | Колонки | Поля по порядку |
|---|---|---|
| Кто направляет | 3 | Фамилия · Имя\* · Отчество / Телефон · Специальность · Район / Место работы (во всю ширину) |
| Выплата вознаграждения | 2 | Тип оплаты · Номер карты\* (только при «На карту») |
| Категория и представитель | 2 | Категория (без внутренней) · Медпредставитель\* (при создании) |
| Вознаграждение за направления | 2 | По категории (галочка) · Свой процент · Свои ставки по группам · **Особые ставки по услугам** · За стационар · % · фикс |

- Поле «Номер» из формы убрано: номер присваивает триггер базы (мигр. 121). В заголовке окна
  правки номер показывается: «Источник направления № 0012». В списке колонка «Номер» остаётся.
- «Номер карты» виден только при «На карту» и тогда обязателен (`requiredWhen`). При
  сохранении с любым другим типом оплаты колонка `card_number` очищается (`beforeSave`), чтобы
  старый номер не лежал у партнёра, которому платят наличными.
- «Категория» — только категории без флага `is_internal`: внутренних врачей заводит триггер из
  списка сотрудников (мигр. 122), и выбрать «Внутренние врачи» для внешнего партнёра — ошибка.
  Для этого реестр (`schema-registry.js`) разрешает фильтр `is_internal` у
  `referral_source_categories`.
- «Медпредставитель» владелец в последовательности не назвал, но поле обязательно при
  создании с 2026-10-31 (REFERRAL_REP_ON_CREATE_V1) — остаётся, рядом с категорией.
- Варианты типа оплаты не меняются (наличные / на карту / перечислением): «перечислением»
  описан в шаблоне импорта (`sections.js`), убирать его — отдельное решение.

### 2. Особые ставки по отдельным услугам

Сейчас ставка задаётся по пяти ГРУППАМ услуг (мигр. 153) и либо у категории, либо у источника
(режим «своя»). Владельцу нужно: «за некоторые услуги платим больше общего». Решение —
третий, самый точный уровень: ставка за КОНКРЕТНУЮ услугу у источника.

Порядок выбора ставки за строку счёта (`shared/referral-reward.js`):

```
1. особая ставка источника за ЭТУ услугу (service_rates)        — в любом режиме
2. режим 'own':      ставка группы у источника → свой процент   → 0
   режим 'category': ставка группы у категории → стандартный %  → 0
```

Почему особые ставки действуют в обоих режимах: владелец просит «больше за некоторые услуги»
поверх общей ставки, а общая у большинства партнёров — категория. Заставлять ради одной
услуги снимать галочку и переписывать все ставки категории в карточку — тот самый второй
экран, которого решение 2026-09-08 избегало. Правило «в режиме 'own' категория не читается»
не меняется.

Хранение: новая колонка `referral_sources.service_rates TEXT NOT NULL DEFAULT ''` — JSON-массив
`[{ service_id, unit: 'pct'|'fix', value }]`, по образцу `own_rates` (мигр. 273). Отдельная
колонка, а не записи в `own_rates`: у `own_rates` зафиксированная семантика «читается только в
режиме 'own'», и смешивать в ней два правила — значит объяснять это в каждом читателе.

Права: колонка — деньги, попадает в `moneyColumns` действия «Цены и проценты»
(`permission-catalog.js`); сервер проверяет тем же каталогом (`write-grant.js`).

Отчёты (`rpc/reports.js` `referralLines`): читают `service_rates`, передают `serviceId`
в резолвер; колонка «Режим» у такой строки — «Особая (услуга)», чтобы сумма объяснялась
с экрана. `anyReferralRate` учитывает особые ставки.

Виджет `serviceRatesControl` (`settings-hub.js`, экспорт для теста): таблица «Услуга · Ставка
· убрать», строка добавления — поиск по активным услугам (`searchableSelect`), у услуги
подписана её группа. Пустое значение — записи нет. Услуга, которой больше нет в справочнике,
показывается как «Услуга № N (не найдена)» и не теряется при сохранении.

Карточка сотрудника (внутренние врачи, `referral-reward-editor.js`) особых ставок пока не
показывает: владелец просил карточку внешнего источника. Колонка общая — добавить туда тот же
виджет можно отдельной правкой.
