Статус: дизайн одобрен владельцем в разговоре 2026-11-23 («go on», «go go on»);
этот файл — на его прочтение перед планом реализации.
Источник: `C:\Users\Desinger\Desktop\easymed.uz (Chilla)` — готовый модуль сайта
(спека `docs/specs/2026-09-05-website-module-design.md`, планы W1–W4 там же,

## 1. Что делаем

Публичный сайт клиники (главная, врачи, услуги, отделения, о клинике, контакты,
запись, FAQ, отзывы, новости, правовые страницы, 404) на трёх языках (uz по
умолчанию, ru, en) и всё управление им внутри Easy-Med. Код Chilla
**переносится и подгоняется**, а не пишется заново: он закончен и покрыт
тестами. Меняется только то, чем этот проект отличается от Chilla — права,
лицензия, меню, номера миграций, пакет выпуска, запуск.

Решения владельца (2026-11-23):

| Вопрос | Решение |
|---|---|
| Объём | Все четыре части: сайт, редактор, входящие заявки, аналитика с отчётом |
| Где в меню | Редактор — плитка «Веб-сайт» в «Настройки → Коммерческие инструменты»; входящие «Заявки с сайта» — пункт в колонке CRM, рядом с «Чат с пациентами» |
| Лицензия | Новый модуль лицензии `website` |
| Запуск | Выключен, пока администратор не включит «Сайт включён» |

## 2. Части и где они видны

| Часть | Где | Источник в Chilla |
|---|---|---|
| Публичный сайт | `http://<сервер>:8001/uz/` (`/ru/`, `/en/`) | `server/site/**`, `public/site/**` |
| Редактор «Веб-сайт» | Настройки → Коммерческие инструменты → плитка «Веб-сайт» | `views/website-settings.js`, `rpc/website-content.js`, `rpc/website.js`, `rpc/website-slug.js` |
| «Заявки с сайта» | Колонка CRM, пункт со счётчиком новых | `views/website-requests.js`, `website-labels.js`, `server/site/requests.js`, `server/site/notify.js` |
| Отчёт «Веб-сайт» | Отчёты | `views/website-report.js`, `rpc/website-report.js`, `server/site/analytics.js` |

Вкладки редактора — как в Chilla: Основное, Главная страница, Врачи, Услуги,
Отделения, Отзывы, FAQ, SEO, Новости; загрузка фото; ссылка «Открыть сайт».

## 3. Топология и запуск

Тот же процесс Node, второй слушатель. `server/site/app.js` — отдельное
Express-приложение только с публичными маршрутами: нет сессий, нет `/api/db`,
нет `/api/rpc`, нет статики админки. Порт 8000 (ЕРП) наружу не выставляется
никогда.

**Отличие от Chilla — выключатель.** В Chilla сайт стартует всегда, если не
задан `SITE_PORT=0`. Здесь слушатель 8001 поднят, только когда одновременно:

1. в лицензии есть модуль `website`;
2. в настройках сайта `enabled = true` («Сайт включён» на вкладке «Основное»);
3. `SITE_PORT` не равен `0` (аварийный выключатель остаётся).

Включение и выключение в редакторе действуют без перезапуска сервера: сохранение
настроек и смена лицензии (check-in) пересчитывают условие и поднимают или
закрывают слушатель. Обновление клиники поэтому никогда само не открывает новый
порт.

Рядом со ссылкой «Открыть сайт» — пояснение: при первом запуске Windows может
один раз спросить разрешение для порта 8001 в локальной сети.

## 4. Данные

Одна миграция — следующий свободный номер **на `origin/main`** в момент начала
работы (сегодня это 298; проверить снова перед созданием файла, см. память
`migration-numbers-check-origin-main`). В ней — таблицы Chilla из `083_website.sql`
и `087_website_request_session.sql` одним файлом:

- настройки: `website_settings` (одна строка, JSON);
- содержимое: `website_doctors`, `website_services`, `website_departments`,
  `website_testimonials`, `website_faq`, `website_posts`;
- заявки: `website_requests` (с `session_id` из 087);
- аналитика: `website_sessions`, `website_pageviews`, `website_stats_daily`.

Только добавление, ни одна существующая таблица не меняется. Перед переносом
схему сверить с этим проектом: имена и столбцы `users`, `services`,
`departments`, `crm_requests`, `crm_request_services` могли разойтись с Chilla
за три месяца раздельной жизни — расхождения правятся в переносимом коде, а не
в существующих таблицах.

Ничего не публикуется само: у каждого врача, услуги и отделения — явная
отметка «Опубликовать» и своё публичное описание.

**Доступ.** `website_settings`, `website_requests` и таблицы аналитики — только
через серверные обработчики, в реестр `/api/db` не входят (как
`telegram_settings` с токеном бота). Таблицы содержимого — как решил Chilla
(реестр с записью по праву «Веб-сайт»), если реестр этого проекта это
допускает; иначе — тоже через обработчики.

**Фото.** Новая корзина хранилища `website` в `BUCKETS`
(`server/routes/storage.js`). Публичный сайт отдаёт только из неё, только
разрешённые расширения, с защитой от выхода за папку.

## 5. Права и лицензия

- **Лицензия.** Модуль `website`. Без него: слушатель 8001 не поднимается,
  плитка, «Заявки с сайта» и отчёт показывают экран предложения, как другие
  некупленные модули. Серверные обработчики сайта отказывают так же.
- **Роли.** Права «Веб-сайт» — строками каталога прав
  (`public/js/shared/permission-catalog.js`) в блоке «Коммерческие инструменты»
  с обычными уровнями (нет / просмотр / изменение). Каждый обработчик сайта
  проверяет право на сервере. Администратор — по умолчанию.
- **Панель вендора.** `website` добавляется в `SELLABLE_MODULES`
  (`control-plane/public/panel-logic.js`). Пока развёрнутая контрольная плоскость
  на settings.easymed.uz не обновлена, выдать модуль клинике нельзя — это
  отдельный шаг владельца, не часть выпуска клиник.

## 6. Заявки с сайта

Как в Chilla (§6 его спеки): сайт принимает **заявки**, клиника подтверждает их
звонком; жёсткой записи на слот нет. Одна транзакция: строка
`website_requests`; для записи на приём — ещё карточка CRM (`source='website'`,
«Сайт») и строка услуги. Дальше работает существующий CRM: доска, сопоставление
с пациентом по телефону, регистратура. Обращения «контакт» и «перезвонить»
живут только во входящих, пока сотрудник не нажмёт «Создать заявку в CRM».

Перед переносом сверить, как этот проект сейчас заводит карточку CRM (за три
месяца CRM здесь заметно изменился: «Записи CRM», статусы, источники) — новая
заявка должна выглядеть как заведённая обычным путём.

Уведомление сотрудникам — Telegram-бот клиники, если задан чат (как в Chilla).

## 7. Аналитика

Как в Chilla (§10): собственные данные, без внешних сервисов и без личных
данных. Сессия — случайная кука, IP не хранится (только ежедневно солёный хэш
у заявок), сырые просмотры удаляются через `retention_days` (90), дневные
итоги хранятся всегда. Отчёт: посетители, страницы, источники, заявки,
конверсия, исходы заявок в CRM.

## 8. Пакет выпуска

`server/site/**` и `public/site/**` (включая шрифты Manrope и `logo.webp`)
должны попасть в разрешённый список подписанного пакета
(`scripts/build-bundle.mjs`) с тестом, что они действительно внутри. Иначе
клиника обновится и получит сайт без стилей.

## 9. Что меняется относительно Chilla

1. Выключатель — лицензия + «Сайт включён», без перезапуска (§3).
2. Права — каталог прав этого проекта вместо `NAV_MODULES` Chilla.
3. Меню — плитка в «Коммерческих инструментах» и пункт в колонке CRM вместо
   отдельного пункта бокового меню Chilla.
4. Руководство по публикации в интернете (`docs/website-hosting.md`) переписать:
   NSSM и служба Windows здесь не существуют, установка — лаунчер `EasyMed.exe`.
5. Иконки — из `public/js/admin/icons.js` этого проекта, строки — через
   `i18n-strings.js`, без эмодзи.
6. Незакрытые мелочи из «ledger» Chilla (§0 его спеки) не переносятся как
   работа — остаются незакрытыми, как там.

## 10. Этапы

После каждого этапа — полный `npm test` зелёный, владелец смотрит на
localhost, и только тогда следующий.

1. **Основа и публичный сайт.** Миграция, второй слушатель с защитой
   (заголовки, лимиты, размер тела), все страницы на трёх языках, форма записи
   в CRM, sitemap/robots. Сайт поднимается, только если включён.
2. **Редактор.** Плитка «Веб-сайт», все вкладки, фото, права «Веб-сайт»,
   ворота лицензии.
3. **Входящие.** «Заявки с сайта» в колонке CRM со счётчиком, «Создать заявку в
   CRM», уведомление в Telegram.
4. **Аналитика.** Счётчик посещений и отчёт «Веб-сайт».
5. **Пакет и плоскость.** Разрешённый список пакета, `website` в панели
   вендора, руководство по публикации.

## 11. Проверка

- Тесты Chilla переносятся вместе с кодом. Главные — безопасность: сайт не
  отдаёт ничего от админки; неопубликованное и поля пациентов, сотрудников,
  денег не появляются ни в одном публичном ответе; лимиты срабатывают; выход
  за папку в `/media` закрыт.
- Новые тесты: слушатель не поднимается без лицензии или без «Сайт включён» и
  закрывается при выключении; обработчики сайта отказывают без лицензии и без
  права; файлы сайта внутри пакета выпуска.
- Остальной набор остаётся зелёным.

## 12. Чего не делаем

Ничего не выкладываем на GitHub, не меняем версию, не ставим тег без отдельного
«да» владельца. Сайт в интернет не выводится — это руководство по публикации,
шаги делает владелец, когда у клиники будет домен. Личных кабинетов пациентов,
онлайн-оплаты и жёсткой записи на слот нет (как в Chilla).
