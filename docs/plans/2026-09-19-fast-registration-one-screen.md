# «Быстрая регистрация» in one window — design + plan (FAST_REG_ONE_SCREEN_V1)

**Date:** 2026-09-19 · **Owner's ask:** the patients toolbar stays as it is; the «Быстрая регистрация» button must open ONE window like the reference screen: «Реквизиты пациента» on top, an «Услуги» table below (doctor per row), with «Печать», «+Пакеты», «+Услуги», and a save action. Today the button opens the patient form and then a second window (the visit wizard) — FAST_REGISTRATION_V1. This replaces that.

## Design

**Window.** A `.modal-card.modal-grouped.mg-dense` at 1240 px (the widest card in the product, same inline sizing as the patient form), body scrolls. Two stacked blocks inside `.modal-body`:

1. **«Реквизиты пациента»** — the patient form's own field set (sections «Личные данные», «Документы и резидентство», «Контакты и адрес»; the «Здоровье» section is left for the patient card). Same required fields (фамилия, имя, дата рождения, пол), same duplicate check. One extra dialog-level field in the same grid: **«Код отправителя (лечащий врач)»** — a searchable select over `referral_sources` labelled `код · имя` (shared/referral-label.js), written to the visit (`ensure_visit.referral_source_id`), never to the patient. «Тип скидки» is the existing «Категория пациента» select (`patients.category_id`), whose discount rules the server applies.
2. **«Услуги»** — a `.card` with `.card-header` (title, count) and a `table.tbl`: **№ · Наименование · Сумма · С НДС · Врач · Уд.** «С НДС» is the catalogue price (prices are VAT-inclusive in this product); «Сумма» is the price net of VAT (`price / (1 + tax_rate/100)`) — presentational, exactly like the Excel export's VAT_INCLUSIVE_V1 math; the invoice is unchanged. «Врач» is a native `<select>` filled from `doctorPoolFor(doctors, service)`; required when `service.requires_doctor`. «Уд.» removes the row. Header buttons: **«+Услуги»** → the existing catalogue picker in pick mode (`openServicePickerModal({ onPick })`, each pick appends a row; a picked doctor pre-selects the row's doctor); **«+Пакеты»** → a template picker (list of active `service_templates`; choosing one appends its services); **«Печать»** → disabled until saved, then prints the invoice sheet (`printableSheet({type:'invoice'})`, same payload shape as the wizard).

**Footer.** «Отмена» and the primary **«Сохранить»** (Enter). Product convention keeps primary actions in `.modal-foot`; the reference puts it in the header — a placement, not a behaviour, difference.

**Save.** `collect()` → `savePatient(payload)`; on `DUPLICATE_PATIENT` the existing duplicate dialog offers «Открыть существующего» → in this window that means **use that patient for the services** (no navigation), or «Создать всё равно». With no service rows: the patient is saved and the window closes (same as the plain form). With rows: `registerWalkIn()` — a new headless module: first active branch → `ensure_visit` (now, `visit_type:'outpatient'`, `referral_source_id`, first row's doctor as visit doctor) → `service_price_quote` for the patient (an existing patient may be on a second/repeat visit) → one `visit_services` insert per row (`quantity 1`, quoted `unit_price`/`total`, `price_tier`, `doctor_id`, `status 'added'`, `created_by`) → `create_invoice_for_visit({ visit_id, visit_service_ids, discount_amount: 0, payer_id: null })` (patient pays; the server applies the category discount — verified in billing.js by the implementer, else computed client-side like the wizard's loyalty %) → `issue_queue_numbers`. Any failure after `ensure_visit` leaves the visit without an invoice, exactly like the wizard, and is reported in a toast.

**After save.** The window stays open in a «saved» state: header shows «Пациент № MRN», the form is read-only, the table shows queue numbers, «Печать» is enabled (prints the invoice), plus «Открыть карту» and «Закрыть». `onSaved()` refreshes the patients list behind.

**Access.** The new dialog calls `canCreatePatient()` itself and shows `openAccessDeniedDialog()` otherwise — the same gate as the patient form (PATIENT_CREATE_GATE_V1). `patients.js` keeps exactly one `openPatientCreateModal(` call and one `=> openFastRegistration()`; the button now opens the new dialog via `await import('./fast-registration.js')`. The two-window quick mode in the patient form (title/hint/primary swap) is removed with its two tests.

**Out of scope.** Payer split, scheduling to a slot (walk-in = now), «Подтверждение» and «Пов.» columns of the reference (statuses that exist only after the visit), pre-save printing, «Физиотерапия», «Результаты PDF».
