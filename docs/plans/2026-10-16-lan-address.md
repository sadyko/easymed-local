# LAN_ADDRESS_V1 — «всегда IP»: предупреждение о смене адреса и постоянное имя в сети

> Короткий план (владелец: «оба варианта»). Исполнение — test-driven-development,
> шаг = коммит. Маркер во всех файлах: `LAN_ADDRESS_V1`.

**Беда.** Компьютер-сервер клиники после каждого перезапуска получает от роутера
новый адрес (192.168.1.147 → .156 → .145). Остальные компьютеры и анализаторы
(порт 2575) теряют сервер. Настоящее лечение — резервирование адреса в роутере
(DHCP reservation); программа должна (1) заметить смену и сказать
администратору, как закрепить адрес, и (2) дать компьютерам имя, которое не
меняется: `http://<имя>.local:8000`.

**Что выяснено в коде (до плана).**

| Вопрос | Ответ |
|---|---|
| «Имя в адресе» есть? | Да: `api_settings.slug` (мигр. 242, `readSlug(db)` в `server/services/api/connections.js`; `[a-z0-9-]`, 3–40 — готовая метка DNS). Живёт в главном здании; пусто → «easymed». |
| Где показывать | «Настройки → Настройки Easy-Med». «Система» владелец оставил «только версия и что нового» (SETTINGS_SPLIT_V1), поэтому — новая плитка «Адрес в сети» (маршрут `lan-address`, как `clinic-data`). Предупреждение — баннер+колокол администратора через существующий `notifications.js` (NOTIF_CENTER_V1). |
| Где помнить адрес | Файл `data/lan-address.json` (как `data/lisproxy.json`): адрес — свойство этого ПК, не данных клиники; восстановление копии базы и связь зданий его не трогают. Миграции нет. |
| Брандмауэр | `install/launcher/EasyMed.cs` только ПЕЧАТАЕТ команду `netsh … protocol=TCP localport=<port>` (правило «EasyMed (clinic network)»), прав администратора не просит; для 2575 нет ничего. Делаем так же: экран показывает команду для UDP 5353. |
| Новые пакеты | Нет: только `node:dgram`, `node:os`, `node:fs`. |
| Отпечаток лицензии | `computeFingerprint` (checkin.js) не трогаем и не импортируем в новый код. |
| Тесты | `rpc/index.test.js` вызывает КАЖДЫЙ обработчик → под `NODE_TEST_CONTEXT` mDNS выключен, пока тест явно не включит (`EASYMED_MDNS=1` или опция). |

## Устройство

```
server/services/lan/interfaces.js   чистые функции: какие адаптеры настоящие, смена адреса
server/services/lan/state.js        data/lan-address.json: адреса прошлого запуска, смена, «скрыто», выключатель имени
server/services/lan/mdns-packet.js  разбор запроса и сборка ответа DNS (RFC 1035/6762), без сокетов
server/services/lan/mdns.js         ответчик: dgram udp4 reuseAddr, 224.0.0.251:5353, проба имени, конфликт → имя-2
server/services/lan/index.js        запуск из server/index.js, такт 60 с, состояние для RPC
server/services/rpc/lan-address.js  lan_address_status (чтение) / lan_address_dismiss / lan_address_mdns (админ)
public/js/admin/views/lan-address.js  экран «Адрес в сети»
public/js/admin/notifications.js      +уведомление «Адрес сервера изменился» (только админ), крестик → lan_address_dismiss
```

### Правила (решения плана)

- **Настоящие адаптеры:** IPv4, не `internal`, не 169.254.x.x (нет DHCP). Виртуальные/VPN
  по имени (VirtualBox, VMware, vEthernet/Hyper-V, WSL, Docker, TAP/TUN, WireGuard, OpenVPN,
  Tailscale, ZeroTier, Hamachi, Radmin, VPN, Bluetooth, Npcap, Loopback) и по MAC
  (00:05:69, 00:0c:29, 00:1c:14, 00:50:56, 08:00:27, 0a:00:27, 00:15:5d, 02:42:, 00:ff:)
  отбрасываются. Если после отбора не осталось ничего — берём все IPv4 (не пусто, если
  сеть есть). Порядок — по имени адаптера, затем адресу. Никогда не бросает.
- **Смена адреса:** `detectChange(prevAddrs, curAddrs)`. Нет текущих адресов (кабель
  выдернут) → не смена и не запоминать. Первый запуск → не смена. Смена = хотя бы
  один прежний адрес пропал (новый появившийся рядом — не смена: старый адрес
  работает). `from` = прежние, `to` = текущие.
- **Файл:** `{ v:1, addresses, adapters:[{adapter,address,mac,netmask}], seen_at,
  change:{from,to,at}|null, dismissed_at, mdns_enabled }`. Смена записывает новый
  `change` и сбрасывает `dismissed_at`; без смены прежний `change` хранится (админ
  мог не входить между перезапусками). «Скрыть» = `dismissed_at = change.at` —
  до следующей смены. Испорченный файл = пустая память (не падать).
  Проверка — при запуске и каждые 60 с (адрес меняется и без перезапуска).
- **Имя:** `readSlug(db) || 'easymed'` + `.local`. Конфликт: при старте 3 пробы
  (запрос A/ANY, 250 мс) — кто-то ответил на имя другим адресом → `имя-2`, `-3`…`-9`,
  затем состояние `conflict`. Во время работы: чужой ответ с нашим именем и
  другим адресом → меньший IPv4 оставляет имя (и сразу объявляет себя), больший
  переходит на следующее имя (детерминированно, без качелей). Свои пакеты
  (источник = наш адрес) игнорируются. Смена имени в «API» подхватывается тактом.
- **Ответ:** на A и ANY для нашего имени. Адреса — из подсети спрашивающего
  (по маске), иначе все. Источник-порт ≠ порт ответчика → «legacy unicast»:
  ответ на адрес/порт спросившего, тот же ID, вопрос повторён, TTL 10, без
  cache-flush. Иначе — multicast на 224.0.0.251:5353, ID 0, TTL 120,
  cache-flush (класс 0x8001). Флаги ответа 0x8400 (QR, AA).
- **Никогда не ронять сервер:** ошибка сокета (порт занят, multicast запрещён,
  брандмауэр) → одна строка в журнал (`logOnce`), состояние `failed` с причиной,
  сервер работает дальше. Выключатель: `EASYMED_MDNS=0|off` (env) или
  `mdns_enabled:false` (кнопка на экране, админ). Под `node --test` выключен,
  пока не задано `EASYMED_MDNS=1` или опция `allowUnderTest`.
- **Брандмауэр:** экран говорит: «Если имя не открывается на других
  компьютерах — на этом компьютере один раз выполните от имени администратора:
  `netsh advfirewall firewall add rule name="EasyMed (имя в сети)" dir=in action=allow protocol=UDP localport=5353`».
  И честно: анализаторы адрес вписывают числом — им имя не поможет, только
  резервирование.

### RPC

- `lan_address_status` (любой вошедший; READ_ONLY_RPCS) → `{ addresses:[{adapter,address,mac,netmask}],
  port, change:{from,to,at}|null (null, если скрыто), name:{ base, current, url, state, reason, suffixed }, mdns_enabled, router_hint }`.
- `lan_address_dismiss {at}` (админ; ALWAYS_ALLOWED_RPCS — файл ПК, не данные клиники) → статус.
- `lan_address_mdns {enabled:boolean}` (админ; ALWAYS_ALLOWED_RPCS) → статус; включает/выключает ответчик сразу.

## Шаги (каждый — тест красный → код → зелёный → коммит `msgs/lan-<n>.txt`)

1. **План** — этот файл.
2. **`interfaces.js`** — `realLanInterfaces(ifaces)`, `detectChange(prev, cur)`, `formatMac(mac)`
   (как в ipconfig: `A4-BB-6D-12-34-56`), `routerHint(addr, mask)`. Тесты: Wi-Fi+VirtualBox+vEthernet+
   loopback+169.254 → один адрес; всё виртуальное → всё; `.147→.156` — смена; `+.10` — не смена;
   пусто — пропуск; мусор на входе — `[]`.
3. **`state.js`** — `recordAddresses(dir,{interfaces,now})`, `readLanState`, `dismissChange`,
   `setMdnsEnabled`. Тесты на временной папке: первый запуск, смена, повтор без смены хранит смену,
   скрыть → нет; следующая смена → снова видно; испорченный JSON.
4. **`mdns-packet.js`** — `parseMessage(buf)` (сжатие имён, защита от петли), `buildResponse`,
   `buildQuery`. Тесты: байты запроса руками → ожидаемые байты ответа (multicast и legacy);
   QU-бит; ответ с A-записью разбирается; обрезанный пакет → null.
5. **`mdns.js`** — `createMdnsResponder({...})`, `mdnsAllowed(env)`, `nextName`. Тесты: выключатель
   (env/тест/опция); интеграция на тестовом порту 127.0.0.1 — запрос получает наш адрес; «чужой»
   сокет отвечает на пробу → ответчик берёт `имя-2`, на `имя` молчит; конфликт во время работы —
   меньший адрес остаётся; ошибка bind → `failed`, без исключения.
6. **Подключение** — `lan/index.js` (`startLanAddress`, `lanStatus`), `rpc/lan-address.js`, RPC-карта,
   `gate.js`, `server/index.js`. Тесты: RPC-контракт, права (не админ не скрывает), выключатель
   запускает/гасит ответчик (фабрика подменена).
7. **Экран** — `views/lan-address.js`, плитка в хабе, маршрут в `admin.js`/`permissions.js`,
   строки ru/uz/en в `i18n-strings.js`, CSS (`--fs-*`, 360 px). Тесты в стиле `system-view.test.mjs`:
   адреса, MAC, имя, предупреждение и «Скрыть», инструкция по роутерам, кнопки только админу.
8. **Баннер** — `notifications.js`: уведомление для админа, крестик/«Скрыть» → `lan_address_dismiss`.
   Тест в стиле `inpatient-notifications.test.mjs`.
9. **Проверка глазами** — Playwright 1280/360 на своём сервере (случайный порт, временная папка
   данных); i18n-стражи; узкие наборы в ru и en-US.

Не делаем: AAAA/IPv6, NSEC-отрицания, правку лаунчера (EasyMed.cs — отдельная поставка),
автоматическое правило брандмауэра (нужны права администратора).
