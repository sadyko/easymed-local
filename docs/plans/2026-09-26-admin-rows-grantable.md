# Строки «Только администратор» становятся выдаваемыми (2026-09-26, ADMIN_ROWS_GRANTABLE_V1)

Владелец (снимок «Настройки → Роли»: «Сотрудники», «Роли», «Telegram-бот» — «Только администратор»):
«there are some roles and functions which are only available to the administrator. can you make read,
change, delete options for them too?»

## Решения
- Каждая закрытая строка получает те уровни, которые экран за ней действительно умеет: Нет / Просмотр /
  Изменение / Удаление. «Удаление» — только там, где удалять есть что:
  - Сотрудники — Нет / Просмотр / Изменение / Удаление (удаление сотрудника без истории);
  - Роли — Нет / Просмотр / Изменение (ролей не удаляют — их отключают);
  - CRM-канбан — Нет / Просмотр / Изменение / Удаление (удалить колонку, источник, метку; колонку с
    заявками по-прежнему удалить нельзя);
  - Телефония — Нет / Просмотр / Изменение / Удаление (удалить подключение провайдера, «забыть» Binotel);
  - Telegram-бот (настройки) — Нет / Просмотр / Изменение (удалять нечего; «Изменение» даёт и рассылку,
    и отвязку чата: тот, кто ставит токен, и так распоряжается ботом);
  - Telegram-бот (отчёт) — Нет / Просмотр;
  - API — Нет / Просмотр / Изменение (переименовать и отозвать ключ; СОЗДАТЬ ключ — только
    администратор, см. ниже; удаления ключей нет вовсе);
  - Скидки, полисы, провайдеры, кэшбэк, ставки врачей — Нет / Просмотр / Изменение (удаления у этих
    таблиц нет ни у кого): вся плитка — деньги, поэтому «Изменение» само даёт и деньги;
  - Помещения получили «Удаление» (оборудование и оборудование помещения — единственное, что там
    удаляет администратор).
- Деньги внутри обычных плиток больше не «только администратор» навсегда: у каждой такой плитки есть
  действие «Цены и проценты» (Нет / Изменение, по умолчанию Нет) — Типы услуг, Консультации врачей,
  Категории пациентов, Список источников, Категории источников, Помещения и Сотрудники (зарплата и
  ставки в карточке сотрудника). Охват лаборатории («Компания») и отдел помещения деньгами не являются —
  они остаются как были.
- Сервер проверяет каждый уровень тем же ключом (grantAllowsOr). Строка, которую роль не настраивала,
  живёт по СЕГОДНЯШНЕМУ правилу — только администратор (`adminDefault`), поэтому после обновления не
  открывается ничего. Экран «Роли» не выводит такие строки из старых галочек (иначе первое же сохранение
  роли раздало бы их).
- Администратор (и администратор дополнительной ролью) сохраняет всё.

## Защиты
1. Роли: не-администратор с «Роли: Изменение» не может править роль `admin` и свою роль клиники на её
   основе, создавать роль на основе администратора (и вообще на основе роли, которой не носит сам),
   поднимать любой ключ/раздел/вкладку выше того, что держит сам (снять ключ = поднять до максимума),
   и править свои собственные роли. Проверка — сервер, единственная дверь /api/db
   (services/role-guard.js из routes/db.js).
2. Сотрудники: не-администратор не назначает роль `admin` (основной, дополнительной, своей ролью на её
   основе), не назначает роль, у которой есть то, чего нет у него, не трогает учётную запись
   администратора (ни правки, ни пароля), не сбрасывает пароль тому, чья роль выше его, не меняет свою
   роль, не удаляет администратора и себя. Проверка — routes/users.js.
3. API: у ключа нет областей доступа — это полный машинный доступ, поэтому создавать ключ и задавать
   его значение может только администратор; «Изменение» переименовывает и отзывает. «Просмотр» видит
   список с замаскированным значением ключа (маскирует компилятор запросов).
4. Телефония/Telegram: ключи, токены и секреты сервер не отдаёт не-администратору ни на каком уровне
   (ключ Binotel и хвост токена приходят пустыми); «Изменение» может задать новые, а пустое поле
   сохранённый ключ не стирает.
5. CRM-канбан: «Просмотр» видит, «Изменение» сохраняет, «Удаление» убирает колонки/источники/метки;
   колонку и источник с заявками по-прежнему удалить нельзя.
6. Администратор всегда при полном доступе; своя роль неизменяема для не-администратора, поэтому
   запереть себя вне «Ролей» нельзя.

## Проход безопасности (ревью, 26.09)
- C1: назначить (основной, дополнительной, своей ролью) можно только ОСНОВУ, которую носит сам
  назначающий; роль сравнивается по КАЖДОМУ ключу справочника действующим уровнем, а не только
  записанным. То же — для пароля, отключения, правки и удаления сотрудника.
- I1: вкладки карты сравниваются тем же разбором, что у сервера (roles.js tabRankOfPerms), по всем.
- I2: не-администратор меняет адрес подключения телефонии только вместе с ключом; адрес «Моих Звонков»
  — только *.moizvonki.ru (у всех). onlinePBX и Binotel: хост зашит, домен onlinePBX — часть пути.
- I3: свой уровень по ненастроенному ключу — не выше настоящих ворот (services/gate-fallbacks.js,
  сверяется тестом с вызовами requireGrant / grantAllows).
- I4: свою зарплату и ставки не-администратор не меняет никогда.
- (a) себя не разжаловать (и снятием дополнительной «admin»); последний администратор считается и по
  дополнительной роли и своей роли на основе администратора. (b) учётную запись сильнее своей не
  трогать вовсе. (c) коды ролей — только строчные.

## Финальный проход безопасности (26.09)
- C1b: роль сравнивается с назначающим ПО ВОРОТАМ, а не уровнями: ворота со списком ролей, которые
  пускают роль и не пускают назначающего, — отказ (медсестра без «отметить выполнение» не выдаёт
  медсестру, которой его даёт код).
- I5: сверка карты ворот обходит весь server/ и любые формы вызова; неразобранный вызов — красный,
  если не записан в список исключений с объяснением.
- Последний администратор — по сохранённой роли; роль администратора не лишается «Настроек», «Ролей»
  и «Сотрудников»; своя роль заводится одним вызовом custom_role_create (обе записи или ни одной,
  права не выше заводящего).
