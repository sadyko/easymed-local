# Баланс пациента, карты с остатком, публичный профиль врача — план

Ветка `feat/deposit-cards-profile` от `main` (95ba569, v3.10.0). Три отдельных коммита:
A — DEPOSIT_WALLET_V1, B — CARD_BALANCE_V1, C — DOCTOR_PUBLIC_PROFILE_V1.

## Слова владельца

1. «deposit should work, because cashier cancels the payment and can actually refund or push to the
   deposit so on the next service it can be paid — e.g. when a doctor made an error: the neurologist
   says after payment and review it's not his patient».
2. Подарочные карты и сертификаты: «amount should be set» — у карты должен быть остаток, который
   уменьшается. Сегодня офлайн `patient_discounts` вида gift_card/certificate остатка не имеет и
   снимает свою полную сумму с КАЖДОГО визита до конца срока.
3. Публичный профиль врача (биография, образование, опыт, сертификаты, повышение квалификации,
   стаж, instagram/telegram, фото, учёная степень, ru/uz/en) — «we need to add them for building a
   proper API for partners». Сам API в этот набор НЕ входит: только хранить и уметь прочитать.

## Что есть сейчас (проверено по коду)

- Депозит (`rpc/deposits.js`): приём создаёт счёт DEP-… и платёж — это выручка в день приёма
  (DEPOSIT_REVENUE_V1). Баланс = принято − потрачено ('spent') − возвращено. Строк 'spent'
  сервер не пишет никогда.
- `record_payment` принимает способ `wallet` («Кошелёк»), он уже исключён из выручки и итога смены
  (`shared/payment-methods.js` INFLOW_SQL), но баланс не списывает — то есть оплатить «с баланса»
  можно было из воздуха.
- Возврат (`refund_payment`) — только деньгами; отмена (`void_invoice`) — только без денег.
- «Отчёт кассира» (`cashier-report.js`) складывает ВСЕ платежи, «кошелёк» тоже — двойной счёт.

## A. DEPOSIT_WALLET_V1 — один журнал баланса на сервере

Решения:

- **Журнал — та же таблица `patient_deposits`**, у неё уже есть формула баланса. Миграция 157
  добавляет `kind` ('deposit' | 'credit' | 'spend'), `payment_id`, `reason`. Строки:
  - `credit` (status 'received', +сумма) — «зачислено на баланс» при возврате; `invoice_id` — счёт,
    откуда пришли деньги, `payment_id` — возвращённый платёж, `reason` — причина кассира;
  - `spend` (status 'spent', −сумма) — оплата с баланса; `invoice_id` и `payment_id` — платёж
    способом `wallet`.
  Формула баланса одна (`domain/wallet.js`), её читают `deposit_balance`, возврат депозита и
  списание.
- **Возврат на баланс** (`refund_payment` с `to_balance: true`): отрицательный платёж по счёту
  способом `wallet` (он не приход — выручка и ящик не меняются, наличные из кассы НЕ уходят) +
  строка `credit` — в одной транзакции. Счёт снова «должен» / гасится отменой, как сегодня.
- **Оплата с баланса** (`record_payment` / `record_payment_split`, способ `wallet`): баланс
  пересчитывается внутри транзакции (IMMEDIATE), меньше суммы — отказ по-русски, иначе платёж
  `wallet` + строка `spend`. Ниже нуля баланс не уходит никогда.
- **Возврат платежа `wallet` по умолчанию идёт на баланс** (никогда не в наличные), если кассир
  явно не выбрал «Вернуть деньгами» (`to_balance: false`) — тогда это наличный возврат из ящика
  (строка `spend` остаётся, баланс не растёт).
- Возврат ПРИНЯТИЯ депозита на баланс запрещён (это `refund_deposit`); `refund_deposit` работает
  только со строками вида 'deposit'. Выдать зачисленный остаток наличными — не в этом наборе
  (см. «Для владельца»).
- Права: admin/cashier, как у остальных денежных RPC. `deposit_balance` остаётся в READ_ONLY_RPCS.
- Отчёты: «Отчёт кассира» перестаёт считать `wallet` приходом. Доля врача не меняется (считается
  по оказанным строкам).
- Экраны: касса — способ «С баланса» (с остатком) и выбор при возврате/отмене «Вернуть деньгами» /
  «Зачислить на баланс пациента»; окно визита (отмена с возвратом, оплата) — то же; мастер визита и
  калькулятор услуг — вернуть «Баланс: Использовать» (для ролей с правом оплаты).
- Между зданиями `patient_deposits` не ездит (как и сегодня); платёж `wallet` ездит как любой платёж.

## B. CARD_BALANCE_V1 — карты и сертификаты с остатком

Решения:

- **Карта — это способ оплаты, а не скидка.** Владелец: «amount should be set» — хранимые деньги.
  Миграция 158: `patient_discounts.remaining` (для существующих gift_card/certificate = amount) и
  журнал `card_ledger` (карта, платёж, счёт, ±сумма). Способ оплаты `gift_card`.
- Списание: `min(остаток, к оплате)`, атомарно (`UPDATE … SET remaining = remaining − ? WHERE
  remaining >= ?`), в одной транзакции с платежом. Остаток 0 / выключена / срок истёк — отказ
  по-русски. Возврат/отмена платежа картой возвращает сумму на карту.
- Промокоды (процент/сумма) не меняются — остаются скидкой счёта.
- **Выручка:** продажи карт через кассу сегодня нет вовсе (карту заводит админ в настройках).
  Погашение картой — НЕ приход (как `wallet`): в ящике и в итоге смены этих денег нет. Если
  клиника продаёт карты за деньги — продажу надо принимать в кассе (решение владельца, см. ниже).
- Экран «Скидки и сертификаты» показывает остаток; мастер/калькулятор/касса показывают остаток
  при выборе карты и не предлагают пустую.

## C. DOCTOR_PUBLIC_PROFILE_V1

- Миграция 159: колонки `users` из белого списка `update_my_doctor_profile` (ФИО ru/uz/en,
  учёная степень ru/uz/en, биография ru/uz/en, четыре списка записей JSON-текстом, стаж, instagram,
  telegram, photo_url). Фото — путь файла из существующего хранилища `doctor-photos`.
- Профиль врача читает их обратно; тост «не хранятся» пропадает сам (сервер вернёт пустой
  `not_stored`).
- Реестр: чтение колонок персоналом; карточка сотрудника показывает/правит поля для админа.
- Филиалы: колонки едут со справочником сотрудников, как остальные поля `users` (кроме фото —
  файл между зданиями не ездит).

## Ревью денег (2026-09-26) — что исправлено

- C1: счёт депозита (DEP-…) не оплачивается и не возвращается через обычную оплату/возврат (ни деньгами,
  ни на баланс, ни картой) — только «Принять/Вернуть депозит»; кнопка возврата у DEP-счёта в кассе скрыта.
- I1: клиент не пишет patient_deposits вовсе (реестр); мигр. 160 — триггеры: строки зачисления/списания
  не меняются и не удаляются, вид не меняется, сумма меняется только у ждущего депозита, удалить можно
  только депозит без денег. Кэшбэк прежнего экрана получает вид `cashback`.
- I2: остаток карты = номинал + журнал; номинал ниже потраченного — отказ; вид карты с оплатами не
  меняется; отрицательный номинал — отказ (мигр. 158 правлена на месте: не выпущена, в dev-базе не применена).
- I3: потолок карты на услуги учитывает её прежние оплаты этого счёта и части одной оплаты.
- I4: кэшбэк начисляет сервер (`credit_cashback`): база — только новые деньги (без баланса и карты),
  один раз на счёт, возврат его откатывает (сколько осталось на балансе).
- M1: полный возврат на баланс в кассе сразу отменяет счёт (галочка). M2: части «с баланса» в оплате
  частями проверяются вместе, отказ называет настоящий баланс. M4: фото врача — только из своего
  хранилища (кнопка «по ссылке» убрана).

## Решения владельца (оставлены как есть)

- Выпущенные до обновления карты начинают с полного номинала.
- Карта — на предъявителя, к пациенту не привязана.
- Явный возврат «деньгами» платежа с баланса выдаёт наличные.
- Баланс пациента — в своём здании (между зданиями не ездит).
- Продажи карт через кассу нет.
- Отчёты по строкам счетов больше не считают счёт депозита услугой — прошлые цифры этих отчётов станут ниже
  на сумму принятых депозитов.
