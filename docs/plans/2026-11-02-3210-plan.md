- Ветка `rc/3.21.0` в easymed.api5. Без `checkout`/`restore`/`stash`/`reset --hard`.
  Перед каждой фиксацией `git diff --cached --name-only` пуст; в индекс — только свои
  файлы задачи; сообщение — по-русски, файлом (`git commit -F`), последней строкой

- Раздел, выполняемый позже, находит места, уже изменённые ранее, ПО СМЫСЛУ (импорты,
  строки выборок, словарь `i18n-strings.js`). Перед вставкой блока словаря — проверить,
  что ключей ещё нет (дубликат ключа ломает стражи словаря).

  прогон — только в R1. Числа «ожидаемых падений» в файлах задач — с копии, сверять по
  смыслу.

  удалять только `cmd /c rmdir`, никогда `rm -rf`.

## Поправки к разделам (важнее текста файлов задач)

1. **U3 — анализы других зданий показываются** с пометкой «Филиал …», как в карте
   пациента (владелец просил «из других документов пациента»). Фильтр `ownWhere` для
   результатов анализов не ставить; тест «чужое здание не видно» заменить тестом
   «результат анализа другого здания виден с пометкой филиала». Протоколы и файлы между
   зданиями не ездят — для них ничего не меняется.
2. **U8 — честный текст отказа.** После U8.1 запись к врачу Б в день, когда у пациента
   есть ПУСТАЯ запись к врачу А, получает `day_visit_busy` с текстом «…по нему уже идёт
   работа…». Дать отдельный код `day_visit_other_doctor` и текст «У пациента в этот день
   уже есть запись к <врач> в <время>. Перенесите её или выберите другой день.» (ru/uz/en;
   онлайн-записи партнёров получают тот же код — проверить их ответ). Плюс: запись журнала
   окна повторного визита (`detail` объектом → 400) — передавать строкой JSON.
3. **U8.2 после U9 и перед U10a.** Вставка строки в `calendar_book` вызывает проверку
   повтора U9 (`assertOrders`) так же, как другие двери. U10a (позже) добавляет туда
   `lineReferralStamp`.
4. **К4 — третья дверь замены.** Напоминание «Перепечатайте этикетку пробирки.» выводит
   и старшая касса «Исправить услуги» при замене лабораторной услуги в оплаченном счёте
   (третий путь замены, U11.8 его не задел).
5. **U4 — своя смена пароля без текущего через PATCH остаётся на сервере** (её держит
   `password-change-v2.test.js`); в интерфейсе поля больше нет. Владельцу сказать.
6. **U1 — «Тип визита»** печатается только у второго/повторного визита (тариф строки);
   у первичного и у консультаций строки нет — так честнее, чем всегда «Первичный приём».

## Ход работы по каждому разделу

1. Исполнитель выполняет задачи раздела по файлу и поправкам, фиксирует после каждой.
2. Проверяющий (только чтение) — по описанию и качеству, с опровергающими пробами.
3. Найденное исправляет исполнитель (тот же или новый), проверяющий смотрит снова.
4. Следующий раздел начинается после того, как предыдущий исполнитель закончил;
   проверка предыдущего может идти параллельно.
