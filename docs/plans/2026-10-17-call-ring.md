# «Звонит» в панели «Телефон» (CALL_RING_V1) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Входящий звонок виден в панели «Телефон» в момент звонка: блок «Звонит» с именем
пациента и кнопками «Открыть карту» / «Открыть заявку» / «Новая заявка»; карта сама не
открывается (решение владельца).

**Architecture:** Станция шлёт вебхук «начало / ответ / конец звонка» на публичный сервер
`api.easymed.uz` (`/_pbx/v1/{clinic}/{token}`), тот держит события 10 минут; клиника забирает их
длинным опросом по подписанному каналу обмена (`GET /_sync/v1/pbx-events?after&wait=20`), пока
есть спрос от открытых панелей; живое состояние звонков — в памяти сервера клиники
(`telephony/live.js`), панель спрашивает его раз в 2 секунды (`telephony_live`). Тот же разборщик
принимает вебхук прямо на клинике (`/api/telephony/pbx/{token}`) и событие Binotel «кто звонит».

**Tech Stack:** Node 24 (`node:test`, `fetch`, `EventEmitter`), Express, better-sqlite3; браузер —
ES-модули без сборки, `h()`/`tr()`, WebAudio для сигнала; стенды `crm-harness.mjs`,
`public-server/server/test-helpers/fixture.js`.

Спецификация: `docs/specs/2026-10-17-call-ring-design.md`.

- Соседняя сессия держит незакоммиченные правки в `admin.js`, `rpc/index.js`, `rpc/telephony.js`,

  сессией). Публичный сервер — `003_pbx_events.sql`.
- `npm test` целиком — не во время прогона соседней сессии; точечно — `node --experimental-vm-modules --test <файлы>`.
- После сборки — СТОП: владелец смотрит dev. Публичный сервер разворачивает владелец.

### Задача 1. Разборщик событий станции (`pbx-event.js`)

- [ ] Тест: onlinePBX JSON `{event:'call_start', direction:'inbound', uuid:'u1', caller:'998901112233', callee:'101', date:1760690000}` → `{uuid:'u1', event:'ring', direction:'in', caller:'998901112233', callee:'101', at:'2026-10-17T…Z'}`; form-строка `event=call_end&direction=outbound&uuid=u2&caller=101&callee=998935550112&hangup_cause=NORMAL_CLEARING&date=…` (уже разобранная в объект) → `end/out`; запасные имена `from`/`to`/`call_id`; `event:'weird'` → `{ unknown: true, keys: ['event', …] }`; пустое/не объект → `null`; Binotel `apiCallSettings` `{externalNumber:'0501112233', internalNumber:'101', generalCallID:'g1'}` → `ring/in`.
- [ ] Реализация: подстроки для `event` и `direction`; номера — только цифры и ведущий плюс (`dialableNumber` из `telephony/dial.js`); `at` — unix секунды/миллисекунды/ISO, иначе `nowIso`.

### Задача 2. Живое состояние и длинный опрос (`live.js`)

- [ ] Тест (память): `noteEvent(db, ring)` → `liveCalls()` = `[{uuid, state:'ringing', direction:'in', caller, callee, since, patient:{id,full_name,mrn}|null, lead:{id,full_name,status}|null}]` — пациент по номеру из `patients`, заявка из `crm_requests`; `answer` → `answered`; `end` → `ended`, через 15 с исчезает; `ringing` без конца — исчезает через 3 мин; повтор `ring` того же `uuid` — одна запись; `demandLive(now)` → `liveDemanded(now+29s)` true, `+31s` false.
- [ ] Тест (опрос): `pullOnce(ctx)` с поддельным `call` — зовёт `GET /pbx-events?after=&wait=20`, кладёт события, второй вызов идёт с `after=<max id>`; отказ сети → `{ ok:false }` и пауза `PULL_BACKOFF_MS`.
- [ ] `public-sync.js`: `export async function buildSyncContext(db, dataDir, opts)` — тело `performSync` до `const ctx` включительно, без `localBlocker`; `performSync` зовёт его и добавляет `localBlocker` отдельно; `export { call }`. Существующие тесты зелёные.
- [ ] `scheduleLivePull(db, dataDir, { everyMs = 250, ... })`: цикл — если не `liveDemanded()` → спать 1 с; иначе `buildSyncContext`; заблокировано → спать 5 с; иначе `pullOnce` (длинный опрос сам держит до 20 с); сбой → `PULL_BACKOFF_MS = 10_000`. `stop()`.

## Исполнение: что разошлось с планом

- **Хеш, а не секрет, на публичном сервере.** Страж схемы (`db/schema.test.js`) не пускает колонки,
  в имени которых есть `token`; колонка называется `clinics.ring_hash` и хранит SHA-256 секрета.
- **Непонятные события** хранятся на публичном сервере строкой `event = 'unknown'` с именами полей
  и клинике не выдаются; на клинике — одна строка в журнал на первые три.
- **Карточка адреса — у плитки onlinePBX**, а не в карточке «WebHook-и» Binotel: это адрес для
  кабинета onlinePBX, и искать его логично там, где настраивают эту станцию.
- **Кнопки «Перезвонить» у сорвавшегося звонка** и «Станция соединяет…» у нашего набора — как в
  спецификации; «Новая заявка» открывает окно доски с подставленным номером через новый аргумент
  `requestModal(r, prefill)`.
