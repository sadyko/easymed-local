# Боковое меню: четыре группы, три свёрнуты, без прокрутки (NAV_GROUPS_V1) — дизайн

Метка: `NAV_GROUPS_V1`. Меняет порядок `NAV` и `renderSidebar()` в `public/js/admin.js`.

## Просьба владельца (2026-10-17)

Снимок бокового меню (17 пунктов под тремя заголовками, колонка прокручивается) и новый
порядок, дословно:

    Block Clinical: Patients, Doctor's Cabinet, Laboratory, Procedures, Inpatient wards,
      Treatment Tasks, Kitchen sheet, Discharges, Documents
    Money Section (it should be Folded): Cashier, Head Cashier
    Operations (it should be Folded): CRM, Patients Chats, Procurement, My Stock
    Settings (it should be Folded): Setting
    Reports (it should be Folded): Dashboard, Reports

И следом: «All of them should fit, and no need for scrolling».

Посмотрев на dev, тем же днём: «put the cashier and head cashier to operations» — группа
«Деньги» упразднена, касса и старший кассир стоят в «Операциях».

Сессия без ответов владельца; решения ниже приняты самостоятельно и проверяются на
dev-сервере до отправки.

## Что сегодня (по коду, ветка `feat/stock-own-shelf-suppliers-vat`)

- `NAV` в `admin.js` — плоский список: записи `{ section }` открывают группу, записи
  `{ id, label, icon }` — пункты. Три группы: Clinical (13 пунктов, включая CRM и
  «Мои запасы»), Operations (чат, касса, старший кассир, закупки), Insights (дашборд,
  отчёты, настройки).
- `renderSidebar()` рисует заголовок группы только когда под ним есть хоть один пункт,
  доступный роли. Внутри лежит мёртвый аккордеон для группы `'Soon'`, которой в `NAV`
  давно нет (`easymed_soon_collapsed`).
- `firstAllowedView()` — домашний экран роли — идёт по `NAV` в его порядке.
- Переводы заголовков — `sidebar.sections.*` в `public/js/admin/i18n.js`; тест
  `app-shell.test.mjs` требует их на трёх языках для каждой секции из исходника.
- На рейке 68px (`.sidebar-collapsed`) заголовки групп скрыты CSS.
- Шаг строки меню 40px (9px полей + 18px значка + 4px зазора), заголовок 35px, шапка с
  логотипом 76px, часы 64px. У администратора всё вместе ≈ 945px — больше окна 1080p с
  панелями браузера (~890px), отсюда прокрутка на снимке.

## Решения

| Вопрос | Решение |
|---|---|
| Группы и порядок | `Clinical` → `Operations` → `Settings` → `Insights` (группа `Money` прожила одну проверку на dev и убрана по слову владельца). Внутри «Операций»: CRM, чат, касса, старший кассир, закупки, «Мои запасы», «Мой отдел» — порядок владельца, а касса за чатом, как стояла до перестановки. Ключи секций английские, как раньше; `Insights` оставлен для группы «Дашборд + Отчёты» (владелец назвал её «Reports», но заголовок «Отчёты» над пунктом «Отчёты» дублирует, а «Аналитика» уже переведена на три языка) |
| Название новой группы | `Settings` — Settings / Настройки / Sozlamalar, как у самого пункта: владелец прямо попросил группу из одного пункта. Перевод `Money` убран вместе с группой |
| Пункты, которых нет в списке владельца | `queue` («Очередь», видна только роли с доской без картотеки) остаётся под «Кабинетом врача», как требует её комментарий. `my-department` («Мой отдел», виден только сотруднику с отделом) едет вместе с «Моими запасами» в «Операции»: оба выдаются одной галочкой и всегда стояли рядом |
| Как свёрнуто | Запись секции получает флаг: `{ section: 'Operations', fold: true }`. Заголовок такой группы — `<button class="nav-section nav-section--toggle" aria-expanded>` с шевроном; список пунктов получает класс `nav--folded`. «Клиника» без флага: всегда раскрыта, заголовок — обычный `div` |
| Что раскрыто | Группа раскрыта, если у неё нет `fold`, или её раскрыли щелчком в этой загрузке страницы, или в ней лежит открытый экран. Последнее считается до цикла (`activeSectionOf`) по родству `PARENT_OF`: журнал движений держит «Операции» открытыми, подэкраны настроек — «Настройки», `report:*` — «Аналитику» |
| Память | Щелчки помнятся в памяти модуля (`navOpened`) до перезагрузки, как `openGroups` у «Настроек» (SETTINGS_HUB_LIST_V1). В `localStorage` ничего не пишется: владелец просил свёрнутое меню по умолчанию. Свернуть группу открытого экрана можно, но следующий `renderSidebar()` (переход) раскроет её снова |
| Рейка 68px | Заголовков на рейке нет, щёлкнуть не по чему, поэтому там свёрнутых групп нет: `.sidebar-collapsed .sidebar-body .nav.nav--folded { display: flex }` |
| Домашний экран | Правило не меняется — первый доступный пункт в порядке меню. Порядок стал другим, и видимое следствие одно: роль только с дашбордом и настройками (не администратор) начинает с «Настроек», потому что их группа стоит раньше «Аналитики». Касса и CRM сохранили прежний взаимный порядок (CRM раньше), так что роль с CRM и кассой по-прежнему начинает с CRM. Отдельного исключения для «Настроек» не вводится без слова владельца |
| Без прокрутки | Шаг строки 33px (7px полей, зазор 1px), заголовок 27px, шапка 62px (верхние 22px не трогаются: они ставят знак клиники на высоту имени раздела — `shell-regions.test.mjs`), часы 50px, поля колонки 4/8px. Замер в headless Chrome при окне 1366×890 у администратора: по умолчанию («Клиника» + три свёрнутых заголовка) — помещается с запасом; все четыре группы раскрыты (18 пунктов) — ≈776px, помещается. При высоте окна ≤760px (ноутбук 768p) ещё плотнее: строка 28px, заголовок 23px, так что состояние по умолчанию входит в ~650px; все группы раскрытыми в 650px не входят — там `overflow-y: auto` у колонки остаётся страховкой |
| Что не меняется | `CRUMBS`, ключи прав, маршруты, бейджи, значки; `.nav-item` вне `.sidebar` (рейки lab-panels и section-crud) не трогаются — плотность задаётся через `.sidebar .nav-item` |

## Поворот (2026-10-27) — NAV_UNFOLDED_V1

Владелец, увидев три свёрнутых заголовка («Операции», «Настройки», «Аналитика»): «make this
unfolded». Группы остаются сворачиваемыми (`fold: true`, кнопка-заголовок), но при загрузке
страницы раскрыты все; щелчок сворачивает группу до перезагрузки (`navClosed` вместо `navOpened`),
группа открытого экрана раскрыта всегда. Меню и так входит в окно без прокрутки (замер выше), а
лишние разделы клиника прячет в «Настройки → Видимость разделов» (NAV_VISIBILITY_V1).

## Тесты (`sidebar-groups.test.mjs`)

1. Из исходника `NAV` разбираются четыре группы в порядке владельца, и в каждой — его
   пункты в его порядке (включая `queue` и `my-department` там, где решено выше).
2. `fold: true` стоит у трёх групп и не стоит у «Клиники».
3. Заголовок `Settings` переведён на три языка, перевода `Money` не осталось (по исходнику
   `i18n.js`: при импорте он трогает `document`).
4. `activeSectionOf` находит группу по предикату; `isNavSectionOpen` — открыта без `fold`,
   по щелчку, по открытому экрану, иначе закрыта; `setNavSectionOpen` ставит классы и
   `aria-expanded`.
5. CSS: `.nav--folded` скрыт, на `.sidebar-collapsed` показан; шаг строки меню задан через
   `.sidebar .nav-item`, а не через общий `.nav-item`.
6. В `admin.js` не осталось `easymed_soon_collapsed`.

Проверка «без прокрутки» — не юнит-тестом, а замером в браузере на dev-сервере:
`scrollHeight <= clientHeight` у `.sidebar-body` при высоте окна 890px со всеми
раскрытыми группами и при 650px со свёрнутыми.
