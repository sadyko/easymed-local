# Ссылки для рекламы в Telegram (диплинки бота) — TG_DEEPLINK_V1 — дизайн

Метка: `TG_DEEPLINK_V1`. Второй инструмент группы «Коммерческие инструменты» (рядом с Meta).

## Просьба владельца (2026-10-26)

Два снимка: плитка «Коммерческие инструменты» и образец из другой системы (бот La Tiva):
таблица ссылок вида `https://t.me/<бот>?start=<ключ>` с названием, типом заявки, двумя
счётчиками (переходы и заявки), переключателем активности, «Изменить / Удалить», и форма
«Новая ссылка»: ключ (латиница, цифры, «-» и «_» — попадёт в ссылку), название, тип заявки
(«Обратный звонок»), ответ бота на RU / UZ / EN, кнопки под ответом («без кнопок бот покажет
одну — «Оставить заявку»»; кнопка может показать другой ответ этой же воронки, открыть
страницу или начать заявку), файл к ответу (PDF или фото до 10 МБ — бот пришлёт его вместе с
ответом). Слова владельца: «and here generation of Deeplink, sample is provided in the photo —
go on now».

## Зачем

Ссылка ставится в рекламу (Instagram, Meta, листовки — своя ссылка на каждый канал или
пакет). Человек открывает бота по ней — ещё не пациент, без номера телефона в базе — и сразу
получает то, ради чего кликнул (прайс, фото палаты, описание пакета), а кнопка «Оставить
заявку» заводит карточку в CRM. По каждой ссылке видно, сколько пришло и сколько оставили
заявку: это и есть измеримая реклама.

## Что сегодня (проверено по коду 2026-10-26)

- Бот (`server/services/telegram/flow.js`): любой человек без привязанного номера получает
  приветствие и кнопку «Поделиться номером»; `/start` с параметром не разбирается; все
  callback-кнопки требуют привязки. Тексты бота двуязычные (узбекский первым).
- Файлы для бота лежат в корзине `telegram-media` (`media.js`, проверка пути), туда же браузер
  грузит баннер рассылки (`/api/storage`).
- Карточки CRM из внешних источников создаются прямым INSERT в `crm_requests` (путь
  `api/bookings.js` createCard / `meta/leads.js`), источник `telegram` в `crm_sources` засеян.

## Решения

| Вопрос | Решение |
|---|---|
| Где в настройках | Плитка «Ссылки для рекламы в Telegram» в «Коммерческих инструментах» → маршрут `telegram-deeplinks`, свой экран |
| Кто видит | Окно «Telegram-бот» в «Ролях» (`settings.telegram`): просмотр — таблица и счётчики, изменение — создание и правка. Ненастроенная роль — только администратор (как у остальных экранов бота). Экран лицензией не закрыт; без модуля `telegram` показывает предупреждение, бот всё равно нужен |
| Ключ | `[a-z0-9_-]{1,32}`, хранится строчными, сравнение без учёта регистра (Telegram передаёт параметр как есть, люди набирают как попало). Уникален. Ссылка — `https://t.me/<bot_username>?start=<ключ>`; имя бота — из `telegram_settings.bot_username`, которое заполняет проверка связи |
| Ответ бота | Три поля: RU, UZ, EN. Язык выбирается по `from.language_code` пользователя Telegram: `uz` → UZ, `en` → EN, иначе RU; пустое поле — откат на RU. Текст до 4096 знаков; с файлом — подпись до 1024, длиннее — текст отдельным сообщением, файл следом |
| Файл | PDF или картинка до 10 МБ, грузится в `telegram-media/deeplinks/<id>/<имя>` через `/api/storage`, отправляется как документ (PDF) или фото. Проверка пути — общая `resolveMedia` |
| Кнопки | Список под ответом, у каждой подпись и действие: показать другой ответ (ключ другой ссылки), открыть страницу (URL), начать заявку. Без кнопок бот показывает одну — «Оставить заявку» на двух языках. Инлайн-клавиатура, callback_data `dl:a:<ключ>` / `dl:l:<ключ>` — никакого состояния диалога, как и в остальном боте |
| Заявка | «Оставить заявку»: если номер чата уже привязан — карточка сразу; иначе бот просит «Поделиться номером» (тот же механизм с проверкой «свой контакт»), помнит ожидание в `telegram_state` (`dl:lead:<chat_id>`), после номера заводит карточку и отвечает «Спасибо, мы свяжемся». Карточка: имя из Telegram, телефон, источник `telegram` (+ `sources`), первая открытая колонка, комментарий «Заявка из Telegram по ссылке «Название» (ключ) · Тип: Обратный звонок · язык». Повторное обращение того же телефона в окне CRM — в открытую карточку, не новая (правило CRM, как у Meta). Карточка не привязывает человека к пациенту: это заявка, а не выдача документов |
| Тип заявки | Словарь из трёх: `callback` («Обратный звонок»), `appointment` («Запись на приём»), `question» («Вопрос»). Пишется в комментарий карточки; колонка — всегда первая открытая |
| Счётчики | «Переходы» — число `/start` с этим ключом (журнал `telegram_deeplink_hits`: чат, пользователь, язык, время; один человек, нажавший дважды, считается дважды — это переходы, не люди; уникальные тоже считаются и показываются подсказкой); «Заявки» — число карточек, заведённых через эту ссылку (`telegram_deeplink_leads`, ссылка на `crm_requests`, при слиянии карточек переносится, как у Meta) |
| Активность | Выключенная ссылка на `/start` отвечает обычным приветствием бота; переход не считается |
| Что не меняется | Привязка номера и выдача документов — как были; обычный `/start` без параметра — как был |

## Данные (миграция `251_telegram_deeplinks.sql`)

- `telegram_deeplinks`: `id`, `key` UNIQUE, `name`, `lead_kind` CHECK IN ('callback','appointment','question'),
  `answer_ru`, `answer_uz`, `answer_en`, `buttons_json` (массив JSON), `file_path`, `file_kind`
  ('photo' | 'document' | ''), `file_name`, `active`, `created_by`, `created_at`, `updated_at`.
- `telegram_deeplink_hits`: `id`, `deeplink_id` (FK, ON DELETE CASCADE), `chat_id`, `tg_user_id`,
  `lang`, `hit_at`.
- `telegram_deeplink_leads`: `id`, `deeplink_id` (FK CASCADE), `crm_request_id` (FK → `crm_requests`
  ON DELETE SET NULL), `chat_id`, `created_at`.

## RPC (`server/services/rpc/deeplinks.js`)

`telegram_deeplinks_list` → `{ bot_username, links: [{…, hits, unique_hits, leads}] }` (просмотр);
`telegram_deeplink_save({ id?, key, name, lead_kind, answer_ru, answer_uz, answer_en, buttons, file_path, file_kind, file_name, active })`
(изменение; проверяет ключ, кнопки, что ключ «показать другой ответ» существует);
`telegram_deeplink_delete({ id })` (изменение). Файл грузится браузером в `/api/storage`, как баннер рассылки.

## Бот (`server/services/telegram/deeplinks.js` + точки в `flow.js`)

- `/start <ключ>` разбирается ДО проверки привязки: активная ссылка → переход записан, ответ на
  языке пользователя (текст, файл, кнопки). Неизвестный или выключенный ключ → обычное приветствие.
- callback `dl:a:<ключ>` → ответ другой ссылки (переход этой ссылки не считается — это навигация
  внутри воронки, не клик по рекламе); `dl:l:<ключ>` → заявка (сразу или после номера).
- В приёме контакта: если есть ожидание заявки — завести карточку и ответить благодарностью;
  привязку номера как пациента делать по-прежнему (человек мог оказаться пациентом).

## Экран (`public/js/admin/views/telegram-deeplinks.js`)

1. Шапка: бот `@имя` или предупреждение «Бот не подключён — ссылки не откроются».
2. Таблица ссылок: название и ключ, ссылка с кнопкой «Копировать», тип заявки, файл, переходы,
   заявки, активна (сразу сохраняется), «Изменить», «Удалить» (подтверждение).
3. Форма «Новая ссылка / Изменить»: ключ с подсказкой и предпросмотром ссылки, название, тип,
   три ответа, кнопки (добавить / убрать строку: подпись, действие, цель), файл (выбрать /
   убрать, до 10 МБ, PDF или картинка), «Добавить ссылку» / «Сохранить».

## Тесты

Миграция; разбор ключа и языка; ответ бота (текст / файл / кнопки, язык, выключенная ссылка);
переход и заявка (сразу и через номер, повтор в окне CRM, перенос при слиянии карточек);
RPC и права; экран в поддельном DOM (таблица, форма, сохранение); словарь; заметки к выпуску.

## Что не делаем

Статистика по дням и графики; UTM-метки вне Telegram; рассылка по тем, кто перешёл (их чаты
и так в «Чате с пациентами», если они привязали номер).
