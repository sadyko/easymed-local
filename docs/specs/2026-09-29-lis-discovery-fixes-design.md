# Как Easy-Med различает анализаторы — правки перед выпуском (LIS_DISCOVERY_FIX_V1) — дизайн

**Статус:** правило «прибор без адреса» утверждено владельцем 2026-09-29 («Yes, like that»).
**Дополняет:** `2026-09-29-lis-analyzer-list-design.md`, `2026-09-28-lis-mindray-codes-design.md`.
**Основание:** независимое ревью 2026-09-29 доказало три ошибки `server/lis/discover.js` на настоящем `ensureDevice`: случаи S2, S4, S5.

---

## Доказанные ошибки

1. **Исправили модель — пробы перестают ложиться (S5).** Шаг 1 `ensureDevice` сверяет строки по адресу с *угаданной* моделью. После того как человек поправил модель («Добавить» или «Изменить»), строка не находится, и следующая проба заводит дубль (`added = 0`). Панели исправленной строки получают «кормится анализатором другой модели», и все пробы уходят в лоток.
2. **«Единственный без адреса» глотает чужие приборы (S1, S2).** Правило не смотрит ни на порт, ни на вид подключения. Строка «Кабель COM», у которой адреса нет никогда, забирает сетевой BS-240. Строка без адреса на порту 5100 забирает другой прибор на 2575. Настоящий прибор так и не появляется в «Найдены в сети».
3. **Два переадресатора на одном ПК сливаются в одну строку (S4).** Первым говорит BC-2800. AutoLumo (профиля нет, модель не угадать) приписывается к строке BC-2800 «по адресу» и не появляется никогда.

## Решение

### Прибор узнаётся по адресу и по тому, КАК ОН СЕБЯ НАЗВАЛ

- **Новая колонка** `lab_devices.sending_app`, миграция 229: MSH-3 первого сообщения, то есть как прибор назвал себя сам. Пишет её только сервер, человек её не правит. Имя и модель человек может менять — различение от этого не зависит.
- **Бэкфилл:** MSH-3 первого сообщения каждой строки (`lab_device_messages.raw`).
- **Шаг 1 — тот же адрес:**
  - если прибор назвался — строка этого адреса с тем же `sending_app` (без учёта регистра), какой бы ни была её модель сейчас;
  - строка этого адреса, ещё не знающая имени: заведённая человеком — берётся и запоминает имя; найденная без имени (старая) — по прежнему правилу модели, и тоже запоминает;
  - другой прибор с того же адреса (другое имя) — **новая находка**;
  - прибор не назвался — только тогда по одному адресу.
- **Шаг 2 — найденный без адреса:** по `sending_app` (у старых строк — по имени). Адрес дописывается.

### «Без адреса» — правило владельца (2026-09-29)

Прибор, добавленный руками без адреса, принимает пробы, только если выполнено всё сразу:
- прибор сетевой (`mllp`) и включён;
- сообщение пришло на **его порт**;
- модель отправителя ему **не противоречит** (угаданная модель есть, у строки модель есть, и они разные — противоречие);
- он ещё не привязан к другому прибору.

С первой пробы он запоминает **имя и адрес** отправителя и дальше принимает только его. Адрес нужен, потому что два одинаковых прибора называют себя одинаково и различаются только адресом. Любой другой прибор появляется в «Найдены в сети». Если таких строк без адреса несколько, берётся та, что знает это имя. Иначе — единственная свободная. Иначе заводится находка.

Бэкфилл пишет строкам только имя, адрес — нет. Иначе строка без адреса и найденная строка того же прибора оказались бы на одном адресе с одним именем, и пробы молча перешли бы от одной к другой. Адрес строка без адреса узнаёт при первой пробе, которую примет.

- **Новый прибор руками — только с адресом.** Поле «Адрес прибора» обязательно; подсказка — «адрес анализатора в сети, например 10.0.0.20».
- **«Кабель COM» и «Папка» в ручной форме больше не предлагаются:** приборы на кабеле COM приходят через переадресатор и появляются в «Найдены в сети» сами. У уже заведённых таких строк значение сохраняется и видно.
- **Старые строки без адреса** (например, «kjkj») продолжают работать со своим прибором, но чужие больше не глотают.

### Меньшие правки ревью

- **Остановка слушателя** (`lis_restart`, `lis_device_delete`) не ждёт открытых соединений прибора: `mllp.js` помнит сокеты и закрывает их.
- **Обрезанное переросшее сообщение** (строка «сообщение больше … — не принято») нельзя «Привязать»: сервер отказывает, кнопки нет. Иначе в бланк легло бы обрезанное число (PLT «25» вместо 250).
- **Одно поле анализатора у двух показателей** проверяется с учётом того, что прибор присылает поле двумя именами: «WBC» и «6690-2» — одно поле (пары код/имя из `lis_device_codes`).
- **Подпись окна «Добавить прибор»** без сырой метки `last_seen_at`: видимый текст связи в подписи уже есть, а сырая метка меняется с каждой пробой и съедала нажатия.
- **Инструкция «Как подключить анализатор»:**
  - прибор появится в «Добавить прибор» → «Найдены в сети»;
  - «Анализатор не появился? Добавить по адресу» и «Ждут первого сообщения»;
  - прибор на кабеле COM — через переадресатор, руками не добавлять.
- **Необязательное (было и до этой работы):**
  - живой опрос перерисовывает таблицу, живую ленту и лоток, только если изменилось видимое (раскрытое «Сырое» больше не схлопывается);
  - значение из одних звёздочек (`***`) — не значение ни у какого типа строки;
  - `lis_device_codes` читает у каждого сообщения только первые 64 КБ (без последней, возможно обрезанной, строки).

## Что НЕ меняется

- **D4:** только подтверждённые человеком сопоставления.
- **Инвариант 1:** нет автовыдачи.
- **D7:** выданный результат не переписывается — `superseded`.
- **Инвариант 2:** сообщение хранится целиком.
- **Правило лотка** LIS_MINDRAY_CODES_V1.
- **Приём не зависит от `added`.**

## Тесты

- **`discover.test.js`:**
  - модель исправили — следующая проба в ту же строку, дубля нет;
  - строка COM без адреса и строка без адреса на другом порту не забирают сетевой прибор;
  - противоречащая модель не забирается;
  - строка без адреса запоминает первого и не берёт второго;
  - два разных имени с одного адреса — две строки;
  - не назвался — по адресу.
  - Прежний тест «единственный прибор без адреса» — с непротиворечащей моделью; противоречие — отдельным тестом.

## Реализация

### Экран — LIS_DISCOVERY_FIX_V1 (экран), 2026-09-29

Сделано всё из раздела «Экран» и необязательный опрос.

- **Ручная форма** (`d9fab41`). Новый прибор: выбора «Подключение» нет, `transport = mllp`. Без адреса сохранение отказывает: «Укажите адрес анализатора в сети — например, 10.0.0.20». Под адресом — строка про кабель COM: такой прибор появится в «Найдены в сети» сам. В «Изменить» — сеть и прежнее значение строки, если оно другое. Адрес там не обязателен, а пустой — с подсказкой «лучше укажите адрес».
- **Лоток** (`178b985`, `7dfe9a7`). `isTruncatedMessage` в `lab-devices-lists.js`: статус `rejected`, строка журнала начинается с `OVERSIZE_DETAIL_PREFIX` сервера. У такой строки нет «Привязать», есть пометка «пришло не целиком — пусть прибор отправит пробу ещё раз», «Отклонить» остаётся.
- **Подпись окна «Добавить прибор»** (`e147cdc`) — без сырой `last_seen_at`.
- **Опрос** (`2304b7a`): таблица, живая лента и лоток перерисовываются, только когда изменилось видимое. Сверх ревью:
  - раскрытое «Сырое» переживает и перерисовку лотка — неверно настроенный прибор кладёт туда каждую пробу;
  - «Изменить» в таблице открывает форму по свежей строке прибора.
- **«Как назвался»** (`4642259`) — `sending_app`, у строки без него — имя; поле входит в подпись окна.
- **Инструкция** (`669be89`) — три строки из раздела выше, на en/uz экраны названы их подписями.
- **Панели** (`f78b251`): ключ поля строится по парам код/имя из `lis_device_codes`. Пары с общим кодом или именем — одно поле: прошивка сменила код, прибор слал и через переадресатор. В отказе — оба написания: «(WBC / 6690-2)».
- **Штампы:** `lists3`, `lab-v17` — в своих коммитах; `lisfields7`, `panelsv8`, `labwords7` — `7c7939b`.

**Отступление.** Отказ привязки экран узнаёт не по статусу 409: до экрана доходит только `error` (`supabase.js`). Любой отказ с кодом, кроме `internal`, показывается словами сервера и предупреждением, после чего лоток перечитывается. Так теперь выглядят и 403/404 этой кнопки. Сбой сервера и связи — как прежде: «Не удалось привязать сообщение: …».
