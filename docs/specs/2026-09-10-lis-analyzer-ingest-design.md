# Приём результатов с анализаторов (LIS_INGEST_V1) — дизайн

**Статус:** форма утверждена владельцем 2026-09-10, ждёт вычитки спецификации
**Первый срез (решение владельца):** движок + симулятор + сопоставление в панелях.
Переадресатор для лабораторного ПК (`.bat`) — следующей фазой.

---

## Что решает

Сегодня лаборант читает числа с экрана анализатора и перебивает их руками в бланк
Easy-Med. Пробирка уже несёт штрихкод Easy-Med, и его никто не использует.

Задача: анализатор отдаёт результаты сам, Easy-Med находит нужный заказ по номеру
пробы и раскладывает значения по показателям бланка. Работа лаборанта становится
проверкой и выдачей, а не набором.

Машины клиник (названы владельцем): **Mindray BS-240** (биохимия), **BC-5300**
(гематология, 5-diff), **CL-900i** (иммунохемилюминесценция), **BC-20**
(гематология, стоит в Corel Med).

---

## Что уже есть — проверено в коде, а не предположено

- **Штрихкод уже печатается.** `views/lab-barcode.js`, шаг «Забор пробы».
  Номер на пробирке — это `visit_services.id` с ведущими нулями.
- **Одна строка `lab_results` на показатель** — ровно то, чем является один
  `OBX` в HL7. Совпадение модели данных полное.
- **`lab_results` уже несёт всё нужное:** `value`, `numeric_value`, `unit`,
  `reference_range`, `flag`, `entered_by/at`, `verified_by/at` (`006_labs.sql`).
- **Конечный автомат уже приводит куда надо.** `visit_services.status`:
  `added → queued → collected → in_progress → resulted → completed`.
  `resulted` — это «Проверить и выдать», то есть шаг живого человека.
- **Редактор панелей — один, и живёт в лаборатории.** `lab-panels.js`,
  вход только через Лаборатория → «Панели» (`LAB_PANELS_BY_SECTION_V1`,
  решение владельца). Второго редактора заводить нельзя.
- **`lab_panel_analytes` уже описывает показатель полностью:** `code`, `name`,
  `unit`, `value_type`, `decimals`, референсы в т.ч. М/Ж и именованные.
- **Образец фонового сервиса рядом:** `server/services/telephony/`
  (`settings.js` + `poller.js` + `webhooks.js`), поднимается из
  `server/index.js`. LIS повторяет эту форму, а не изобретает свою.

### Чего нет

Ничего не слушает сеть. Нет разбора HL7. Нет понятия «анализатор». Сообщение,
не нашедшее заказ, сегодня было бы просто потеряно.

---

## Решения владельца

**D1 — Две дороги внутрь, потому что клиники разные.**
Слушатель живёт внутри Easy-Med (сетевые анализаторы приходят сами). Для машин,
которые в сеть не включены, но подключены к лабораторному ПК, будет отдельный
переадресатор с `.bat`. Дословно: «its varies by clinic for that reason we need to
hardcode the lab machines into server starting and also create .bat file if its
analyzer not connected to the network but lab computer».

**D2 — Номер пробы вводится руками ИЛИ сканируется.** Оба случая штатные.
Значит опечатка — обычное событие, а не сбой: нужен лоток «Необработанные», и
человек обязан видеть имя пациента перед выдачей (существующий шаг «Проверить и
выдать» это уже обеспечивает).

**D3 — Сопоставление поле-в-поле, руками.** Дословно: «we need to edit a panels,
and the fields that machine giving field by field. if we match in the system there
is can be error». Автоматическое сопоставление по коду само по себе решением не
является.

**D4 — Подсказка разрешена, тихое применение — нет.** Очевидные строки приходят
предзаполненными как «предложено», но **панель не сохраняется, пока человек не
подтвердил каждую строку**.

**D5 — Симулятор — инструмент разработки.** Своя папка, простой вид: выбрать
машину, выбрать показатели, «Опубликовать». Без отделки для клиник.

**D6 — Машина побеждает в черновике, публикует человек.** Дословно: «machine wins,
but the technician decides to rewrite and publish». Значение анализатора замещает
набранное руками в **неподтверждённом** бланке; лаборант правит что угодно и сам
выдаёт результат.

**D7 — Выданный результат машина молча не переписывает.** Следствие D6, не новое
решение: замещать черновик — помощь, замещать выданный отчёт пациента — другое
дело. Повторный прогон после выдачи приходит как новый результат, требующий
повторного подтверждения.

## Инварианты

Их нарушение — дефект безопасности пациента, а не вопрос удобства.

1. **Машина печатает, подписывает человек.** Приём НИКОГДА не проставляет
   `verified_by` / `verified_at`. Автовыдачи нет и не будет.
2. **Ничего не теряется.** Каждое сообщение сохраняется сырым до разбора.
   Смазанный штрихкод стоит одного клика, а не повторного забора крови.
3. **Референсы принадлежат клинике, а не прибору.** Диапазоны и флаги берутся
   из `lab_panel_analytes` (правило `041_lab_handling.sql`: «диапазоны зависят
   от анализатора и метода каждой лаборатории»). Прибор используется только
   там, где клиника диапазон не задала.
4. **Имена и единицы — из панели, не из провода.** В бланк идёт «Лейкоциты»
   и `10^9/л`, а не `WBC` и `10*9/L`. Отчёт остаётся на одном языке.
5. **Порт умеет только результаты.** Он не касается пациентов, счетов, оплат,
   пользователей и не может ничего выдать.

## Архитектура

```
   Сетевой анализатор ──HL7/MLLP──┐
                                  ├──▶ server/lis/ ──┬──▶ lab_results (source='analyzer')
   Лабораторный ПК ──.bat (фаза 2)┘                  ├──▶ visit_services.status='resulted'
   Симулятор ─────────────────────┘                  └──▶ lab_device_messages (сырое + исход)
                                                                    │
                                                     существующее «Проверить и выдать»
                                                                    │
                                                        человек выдаёт → completed
```

Три входа — **одна дверь**. Переадресатор и симулятор говорят ровно то же, что и
настоящий прибор: ни у кого нет частного короткого пути. Если результат симулятора
лёг правильно — ляжет и настоящий.

### Несколько приборов и один порт

Слушатель поднимается **один на каждый занятый порт**, а не один на устройство:
два прибора, настроенные на 2575, иначе подрались бы за него, и второй молча не
поднялся бы. Пришедшее сообщение относится к устройству так:

1. по адресу отправителя, если у устройства заполнен `host` (точное совпадение);
2. иначе — по единственному включённому устройству на этом порту;
3. иначе — устройство не определено: сообщение сохраняется с `device_id = NULL`
   и статусом `unmatched` («порт слушают несколько приборов, адрес отправителя
   не задан»). Лечится тем, что клиника проставляет `host` или разводит приборы
   по разным портам.

Разные порты у разных приборов — рекомендованная настройка, и экран «Анализаторы»
предлагает следующий свободный порт при заведении второго устройства.

Правки существующего:

- `server/index.js` — вызов `startLisListeners()` рядом с `schedulePolling()`.
- `public/js/admin/views/laboratory.js` — четвёртая вкладка (`LAB_TABS`, `#labs/devices`).
- `public/js/admin/views/lab-panels.js` — выбор анализатора у панели + колонка
  «Поле анализатора» у показателя. **Правится один существующий редактор**;
  второй копии не заводим (`LAB_PANELS_EDITOR_V1`).

## Схема — миграция `123_lis_ingest.sql`

Номер занять свободный на момент написания: на dev-боксе последняя — `122`.
Если ветка отстала от `origin/main`, номер сдвинуть (коллизии номеров миграций).

```sql
-- Анализаторы клиники.
CREATE TABLE lab_devices (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT NOT NULL,                 -- как лаборатория его зовёт
  profile       TEXT NOT NULL,                 -- ключ профиля: 'mindray-bc-20', ...
  transport     TEXT NOT NULL DEFAULT 'mllp'
                  CHECK (transport IN ('mllp','folder','serial')),
  host          TEXT,                          -- mllp: с какого адреса ждём (пусто = любой)
  port          INTEGER,                       -- mllp: порт слушателя
  folder_path   TEXT,                          -- folder: что просматривать
  serial_port   TEXT,                          -- serial: COM-порт (фаза 2)
  serial_baud   INTEGER,                       -- serial: скорость (фаза 2)
  enabled       INTEGER NOT NULL DEFAULT 1,
  last_seen_at  TEXT,                          -- когда последний раз что-то пришло
  created_at    TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

-- Панель кормится одним анализатором.
ALTER TABLE lab_panels ADD COLUMN device_id INTEGER REFERENCES lab_devices(id);

-- Сопоставление поле-в-поле (D3) и доказательство подтверждения (D4).
ALTER TABLE lab_panel_analytes ADD COLUMN device_code TEXT;
ALTER TABLE lab_panel_analytes ADD COLUMN device_code_confirmed INTEGER NOT NULL DEFAULT 0;

-- Происхождение значения. 'manual' по умолчанию — все прежние строки сохраняют смысл.
ALTER TABLE lab_results ADD COLUMN source TEXT NOT NULL DEFAULT 'manual';

-- Лоток: каждое сообщение, дошедшее до порта, чем бы дело ни кончилось.
CREATE TABLE lab_device_messages (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id        INTEGER REFERENCES lab_devices(id),
  peer             TEXT,                        -- с какого адреса пришло
  raw              TEXT NOT NULL,               -- сырое сообщение, всегда
  sample_id        TEXT,
  visit_service_id INTEGER REFERENCES visit_services(id),
  status           TEXT NOT NULL
                     CHECK (status IN ('applied','unmatched','unmapped','rejected','superseded')),
  detail           TEXT NOT NULL DEFAULT '',
  received_at      TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  resolved_at      TEXT
);
CREATE INDEX idx_lab_device_messages_status ON lab_device_messages(status);
CREATE INDEX idx_lab_device_messages_vs ON lab_device_messages(visit_service_id);
```

`status = 'superseded'` — сообщение по уже выданному результату (D7): сохранено,
показано, но в бланк не применено само.

**В первом срезе реализуется только `transport = 'mllp'`.** Значения `'folder'`
и `'serial'` заведены в `CHECK` заранее, чтобы фаза 2 не требовала миграции:
`'serial'` — переадресатор с `.bat` (D1), `'folder'` — просмотр папки, куда ПО
производителя выгружает файлы. Форма, выбравшая нереализованный транспорт,
сохраняется, но слушатель по ней не поднимается, и экран честно пишет
«транспорт пока не поддерживается».

### Реестр схемы

`server/db/schema-registry.js` — добавления в белый список, иначе чтение и запись
не пройдут:

- `lab_devices` — чтение `ALL_STAFF`, запись `admin`/`lab`
- `lab_device_messages` — чтение `ALL_STAFF`, запись только сервером
- `lab_panels.device_id`, `lab_panel_analytes.device_code`,
  `lab_panel_analytes.device_code_confirmed` — в списки чтения и записи
- `lab_results.source` — **только в чтение**. Ставит сервер, браузер никогда

## Профили анализаторов

Профиль — **данные, а не код**. Добавить CL-900i = добавить файл; это причина,
по которой инженерная работа не переписывается под каждую новую машину.

```js
// server/lis/profiles/mindray-bc-20.js
export default {
  key: 'mindray-bc-20',
  vendor: 'Mindray',
  model: 'BC-20',
  kind: 'hematology',
  transports: ['mllp'],
  defaultPort: 2575,
  channels: [
    { code: 'WBC', name: 'Лейкоциты',   unit: '10^9/л',  type: 'numeric' },
    { code: 'RBC', name: 'Эритроциты',  unit: '10^12/л', type: 'numeric' },
    { code: 'HGB', name: 'Гемоглобин',  unit: 'г/л',     type: 'numeric' },
    { code: 'HCT', name: 'Гематокрит',  unit: '%',       type: 'numeric' },
    { code: 'PLT', name: 'Тромбоциты',  unit: '10^9/л',  type: 'numeric' },
    // ...
  ],
};
```

`channels` — это и есть список, который лаборант видит в выпадающем поле при
сопоставлении, и он же даёт подсказку по D4.

### Что известно о каждой модели на сегодня

| Модель | Транспорт | Каналы | Основание |
|---|---|---|---|
| **BC-20** | Ethernet, HL7 v2.3.1 (также старый «15ID»), двунаправленный | не подтверждены | Приложение C руководства оператора. Подробности Mindray не публикует: «contact Mindray Customer Service Department or your local distributor» |
| **BC-5300** | уточняется | 27 каналов видны на скриншоте владельца: WBC, Neu%, Lym%, Mon%, Eos%, Bas%, Neu#, Lym#, Mon#, Eos#, Bas#, ALY%, LIC%, ALY#, LIC#, RBC, HGB, HCT, MCV, MCH, MCHC, RDW-CV, RDW-SD, PLT, MPV, PDW, PCT | скриншот ПО производителя |
| **BS-240** | TCP/IP, HL7 v2.3.1 **или** ASTM E1394-97 | не подтверждены | «BS-230/BS-240 LIS Interface Manual» (существует, в открытом доступе нет) |
| **CL-900i** | уточняется | не подтверждены | — |
| BC-2800 / BC-3000 Plus | **только RS-232** | **полностью документированы** | Приложение A / D руководств оператора — есть на руках, `analyzer-manuals/Mindray/` |

Профили с неподтверждёнными каналами создаются пустыми или частичными и
дозаполняются по мере получения документации. Неизвестный канал не ломает приём —
он попадает в лоток как несопоставленный (см. «Ошибки»).

## Экран: Лаборатория → «Анализаторы»

Четвёртая вкладка рядом с Очередь · Панели · Статистика. Доступ — тот же
`canEditLabPanels()`, что и у панелей: отдельной настройки в Настройках нет
(решение владельца о том, где живёт лаборатория).

Таблица: название · модель · подключение · вкл/выкл · **когда последний раз
получено сообщение**. Последняя колонка — то, что не даёт молчаливому отказу
длиться неделю: «BC-20 · подключён · последний результат 4 минуты назад» либо
«не отвечает со вторника».

Ниже — **«Необработанные»**: сообщения со статусом не `applied`, с показом сырого
текста, кнопкой «Привязать к заказу» (повторный приём с явным `visit_service_id`)
и «Отклонить». Разрешение ставит `resolved_at`.

## Сопоставление в редакторе панелей

В `lab-panels.js`:

1. У панели — поле «Анализатор» (выбор из `lab_devices`, можно «нет»).
2. У каждого показателя — колонка «Поле анализатора»: выпадающий список каналов
   выбранного профиля.
3. При выборе анализатора очевидные строки предзаполняются и помечаются
   «предложено» (D4). Пометка снимается, когда человек строку подтвердил.
4. **Сохранение панели запрещено, пока остались строки «предложено».** Это
   единственное место, где D4 держится технически, а не на дисциплине.
5. Показатель без `device_code` — законное состояние: он вводится руками.

Сопоставление хранится на показателе (`device_code`), а не в отдельной таблице
соответствий: показатель и есть то, во что кладётся значение, и лишний уровень
косвенности здесь только добавил бы место для расхождения.

## Путь результата

1. Байты пришли → **сырое сообщение записано** в `lab_device_messages`.
2. Разбор `hl7.js`. Не `ORU^R01` → `rejected` с причиной. `QRY^Q02` (прибор
   спрашивает рабочий список) распознаётся и вежливо отклоняется — дверь для
   будущего оставлена открытой.
3. Номер пробы: `OBR-3` → снять префикс `LAB-` (без учёта регистра) и ведущие
   нули → целое → `visit_services.id`. Голые цифры тоже принимаются: сканер
   может передавать префикс, а может нет.
4. Заказ не найден или не лабораторная услуга → `unmatched`, ничего не пишется.
5. Услуга → её панель. Панель привязана к другому анализатору → `unmatched`
   с этой причиной (машина прислала результат не в свою панель). Панель без
   анализатора (`device_id` пуст) → `unmapped`: заказ найден, но клиника ещё не
   сказала, какая машина его кормит. Оба случая видны в лотке и лечатся
   настройкой панели, а не повторным прогоном пробы.
6. Для каждого наблюдения: показатель, у которого `device_code` = `OBX-3` **и**
   `device_code_confirmed = 1`. Неподтверждённые не применяются — D4.
7. Значение: `OBX-5` дословно в `value`. `numeric_value` заполняется только
   если `OBX-2` = `NM` и текст разбирается в конечное число — так `<0.01` и
   `>1000` сохраняют смысл текстом.
8. Флаг: клиника задала диапазон → считаем сами (ниже `ref_low` → `low`, выше
   `ref_high` → `high`, иначе `normal`). Диапазона нет → берём `OBX-8`:
   `N`/пусто → `normal`, `L` → `low`, `H` → `high`, `LL`/`HH`/`AA` → `critical`,
   прочее → `abnormal`. `critical` попадает в существующий счётчик критических
   результатов (`views/reports.js`).
9. Запись: `source = 'analyzer'`, `entered_by` = NULL (строку не вводил человек;
   выдумать пользователя значило бы испортить журнал персонала).
10. `visit_services.status = 'resulted'`. `verified_by`/`verified_at` не трогаются
    никогда (инвариант 1). `sample_collected_at` не подставляется задним числом:
    Easy-Med не выдумывает время забора, которого не наблюдал.
11. Только после успешной транзакции — `ACK`. Прибор, который повторяет при
    `NAK`, здесь помощник, а не помеха.

Только `OBX-11` = `F` (final) или пусто пишутся. Предварительные (`P`) и
неполученные (`X`) сохраняются в лотке, но в бланк не идут.

### Повторный прогон и конфликт с набранным руками

Ключ замещения — `(visit_service_id, показатель)`. Повторный прогон обновляет, а
не дублирует.

- Бланк **не выдан** (`verified_at` пуст): значение анализатора замещает любое,
  включая набранное руками (D6). Лаборант видит пометку «из анализатора» и правит
  что хочет до выдачи.
- Бланк **выдан**: сообщение записывается как `superseded` и показывается в
  лотке как «новый результат по выданному анализу». В отчёт пациента само не
  идёт; вернуть его в бланк — осознанное действие человека (D7).

## Ошибки

| Ситуация | Поведение |
|---|---|
| Неразбираемое или не-ORU сообщение | `NAK`, сохранено `rejected` с причиной |
| Сообщение больше потолка (256 КБ) | `NAK`, соединение закрыто, записано |
| Номер пробы пуст или не читается | `unmatched`, видно в лотке |
| Заказ есть, но услуга не лабораторная | `unmatched` с этой причиной |
| Панель заказа привязана к другому прибору | `unmatched` с этой причиной |
| Часть каналов не сопоставлена или не подтверждена | сопоставленные применены, сообщение `unmapped` со списком остальных |
| Результат по уже выданному бланку | `superseded`, в бланк не применён |
| Ошибка базы посреди сообщения | транзакция откатывается, `NAK` — прибор пришлёт снова |

Правило одно: **клик, а не повторный забор крови.**

## Безопасность

Порт принимает неаутентифицированный TCP в сети клиники. Это честный компромисс:
анализаторы не умеют логиниться. Ограждение:

- Слушатель умеет **только** писать `lab_results` и двигать статус
  `visit_services`. Пациенты, пользователи, сессии, счета, оплаты и цены ему
  недоступны.
- Выдать результат он не может никогда (инвариант 1). Максимальный вред от
  враждебного сообщения — неверные числа перед человеком, работа которого их
  проверить.
- Необязательный список разрешённых адресов (`lab_devices.host`), потолок размера
  сообщения, тайм-аут простоя.
- Каждое сообщение хранится сырым вместе с адресом отправителя: любая аномалия
  восстановима постфактум.
- Порт отделён от HTTP-порта и закрывается брандмауэром независимо.
- Выключенный `lab_devices.enabled` = слушателя нет вовсе.

## Симулятор (`tools/lis-simulator/`)

Отдельная папка вне приложения. Не поставляется клиникам, в сборку не входит.

- Выбрать модель → показать её каналы → ввести значения → номер пробы →
  «Опубликовать» → отправить настоящий `ORU^R01` по MLLP на адрес Easy-Med.
- **Захват** (добавлено 2026-09-10 после вопроса владельца «как мы можем быть
  уверены, что заработает в реальной клинике»): режим «слушать и записать» —
  поднять порт, сохранить всё пришедшее в файл как есть. Двадцать строк, но
  именно они превращают первый выезд в клинику из «не заработало» в сырые байты,
  по которым видно причину. Владелец может вычеркнуть этот пункт при вычитке.
- Тот же протокол, что у настоящего прибора. Частного короткого пути нет.

## Тестирование

Всё, кроме последнего пункта, проверяется **без анализатора** — это и есть
причина, по которой первый срез безопасно строить до выезда в клинику.

- `server/lis/hl7.test.js` — чистый разбор: правильный ORU, сегменты по кускам,
  `\r\n`, свои разделители в `MSH-2`, пустой `OBR-3`, не-ORU, форма ACK.
- `server/lis/mllp.test.js` — кадрирование, сообщение, разорванное между
  записями, два сообщения в одном соединении, перебор размера, содержимое
  ACK/NAK. Порт брать через `server/test-helpers/listen.js` (динамический
  диапазон Windows пересекается со списком запрещённых портов `fetch`).
- `server/lis/ingest.test.js` — на свежей мигрированной базе: совпадение по
  `LAB-000123` и по голым цифрам; неизвестная проба → `unmatched`; **показатель
  с `device_code_confirmed = 0` не применяется** (D4); диапазон клиники бьёт
  диапазон прибора; имя и единица берутся из панели; `<0.01` остаётся текстом с
  пустым `numeric_value`; повторный прогон обновляет, а не дублирует;
  `verified_by` остаётся пустым (инвариант 1); `sample_collected_at` не тронут;
  выданный бланк не переписан, сообщение `superseded` (D7).
- `server/db/migrations/123.test.js` — по образцу существующих: `source`
  по умолчанию `'manual'` у ранее существовавших строк.
- `server/services/rpc/lis.test.js` — роли: лаборант правит устройства,
  регистратор не может; лоток не отдаёт чужого.
- `lab-panels` — тест на запрет сохранения панели с неподтверждёнными строками.
- Сквозная проверка симулятором: опубликовать → увидеть значения в реальном
  бланке Easy-Med → выдать.

`npm test` = `node --test` без пути (форма с каталогом ломается на Windows/Node 24).

## Чего нельзя проверить со стола

Строится с этим знанием, а не вопреки ему.

1. Включён ли LIS-выход на приборе и можно ли направить его на наш адрес.
2. HL7 или старый «15ID» (BC-20 умеет оба).
3. Для последовательных машин — порт и скорость.
4. Точные имена каналов у каждой модели.

**Пункт 4 — не дефект, а выпадающий список.** Неизвестное имя попадает в лоток
сырым, лаборант один раз выбирает нужный показатель. Ошибка в догадке стоит
клика, а не переделки.

Что нужно получить из поля, по убыванию ценности:

1. **`BC20.py` из Corel Med** — рабочая реализация для настоящей машины;
   закрывает пункты 1–4 для BC-20 одним файлом.
2. **Руководства от дистрибьютора Mindray** — «LIS Interface Manual» выдаётся
   владельцам приборов бесплатно, просто не публикуется.
3. **Один захваченный настоящий обмен** — закрывает вопрос имён окончательно.

Первый выезд в клинику — **проверка, а не запуск**.

## Вне объёма

- Переадресатор для лабораторного ПК и `.bat` — фаза 2 (решение владельца).
- Транспорт ASTM E1381/E1394 — второй модуль за тем же приёмом, когда понадобится.
- **Исходящие рабочие списки** (`QRY^Q02`): прибор спрашивает, какие тесты делать
  для отсканированной пробирки. Полезно позже; сегодня разбор его узнаёт и
  внятно отклоняет, чтобы дверь осталась открытой.
- Автоматическая выдача результатов — исключена инвариантом 1, навсегда.
- Импорт справочника панелей — клиника строит панели сама, как и сейчас.
