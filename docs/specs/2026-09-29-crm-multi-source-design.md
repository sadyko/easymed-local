# CRM: несколько источников — в фильтре доски и у самой заявки (CRM_MULTI_SOURCE_V1) — дизайн

**Статус:** владелец 2026-09-29: «can we setup multiple source selection in the crm» → на вопрос «где?» ответ **«Both»**.
- Фильтр доски — несколько источников сразу.
- У одной заявки — несколько источников: «пришла из Instagram и по совету знакомых».
- Отчёты считают заявку в каждом её источнике.

Войдёт в выпуск 3.13.0.

---

## Что есть сейчас

- `crm_requests.source` — ОДИН ключ из справочника `crm_sources` (миграция 077).
- Карточка заявки (`crm.js`, «Источник» — чипы, один выбор, `srcChosen`), фильтр над доской (`state.source`, один чип), теги карточки, таблица, Excel, окно «Отчёт» доски.
- На сервере: `callcenter_report` (`server/services/rpc/callcenter.js` ~147 «по источникам», ~320 конверсия по источникам, ~418 выгрузка списка). Заявку пишут ещё `lead-from-call.js`, `booking-mirror.js`, `crm-merge.js`.

## Решение

### Данные
- **Миграция 231** (номер проверить: свободен и в дереве, и в `origin/main`): `ALTER TABLE crm_requests ADD COLUMN sources TEXT` — JSON-массив ключей, в порядке выбора. Бэкфилл: `sources = json_array(source)` там, где `source` не пуст.
- **`source` остаётся** и всегда равен ПЕРВОМУ ключу `sources` — «главный» источник. На него опираются старые места и соседи, которые пишут заявку сами (звонок → заявка, зеркало записи, слияние). Они продолжают писать только `source`.
- **Правило чтения ОДНО** на сервере и на экране: источники заявки = `sources`, если это непустой массив, иначе `[source]`, иначе `['other']`.
- **Реестр** (`schema-registry.js` `crm_requests`): `sources` читается и пишется теми же ролями, что `source`. Сервер при записи `sources` проверяет его:
  - массив строк, 1–10 ключей;
  - ключи из справочника `crm_sources`, включая отключённые, если они уже стоят у заявки;
  - без повторов.

  Затем сервер сам ставит `source = sources[0]`. Кривой `sources` — 400 словами. Запись одного `source` без `sources` — как сейчас: `sources` сбрасывается в `[source]`, чтобы два поля не разошлись.

### Карточка заявки
- **«Источник»:** те же чипы, но выбирается НЕСКОЛЬКО, повторное нажатие снимает. Порядок выбора сохраняется, первый — главный.
- **Хотя бы один источник обязателен.** Последний чип не снимается, при попытке — подсказка «Нужен хотя бы один источник».
- **Новая заявка** начинает с источника по умолчанию, как сейчас.

### Доска
- **Фильтр «Источник»:** чипы отмечаются по несколько.
  - «Все» снимает отметки.
  - Заявка видна, если ХОТЯ БЫ ОДИН её источник отмечен.
  - Число на чипе — сколько заявок периода имеют этот источник. Заявка с двумя источниками считается в обоих; «Все · N» — число заявок.
- **Карточка на доске и строка таблицы:** все источники, через запятую / тегами.
- **Excel:** колонка «Источник» — все источники через запятую.
- **Окно «Отчёт» доски:** заявка считается в каждом своём источнике; строка «Всего» — число заявок, а не сумма по источникам.

### Отчёт колл-центра (сервер)
- **«По источникам» и конверсия по источникам:** через `json_each` по правилу чтения. Заявка — в каждом своём источнике, «пришли» — тоже.
- **Итоги** считаются по заявкам, не по сумме строк.
- **Выгрузка списка:** все источники через запятую.

## Тесты (обязательные)
1. **Миграция 231:**
   - бэкфилл;
   - повторный накат ничего не меняет;
   - заявка без `source` остаётся с пустым `sources`.
2. **Реестр:**
   - `sources` пишется: сервер ставит `source = sources[0]`;
   - отказы: пустой массив, чужой ключ, повтор, >10 ключей, не-массив;
   - запись одного `source` сбрасывает `sources` в `[source]`;
   - роли — как у `source`.
3. **Правило чтения** — одна функция на экран и одна на сервер, с одинаковыми примерами.
4. **Экран:**
   - выбор/снятие чипов в карточке, последний не снимается;
   - сохраняется массив;
   - фильтр по нескольким;
   - числа на чипах;
   - теги, таблица, Excel;
   - «Отчёт»: заявка с двумя источниками считается в обоих, «Всего» — по заявкам.
5. **`callcenter_report`:** та же заявка с двумя источниками — в обоих разрезах. Заявки от звонка (только `source`) считаются как прежде.
6. **Звонок → заявка, зеркало записи, слияние дублей** продолжают работать. Слияние: оставленная заявка получает объединение источников обеих, главный — у оставленной.
7. **Переводы:** новые фразы ru/uz/en.

## Не меняется
- Справочник источников и его экран.
- Права.
- Остальные поля заявки.
