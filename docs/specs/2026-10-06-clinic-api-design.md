## Цель

Клиника заполняет в EasyMed свой профиль, филиалы, публичные профили врачей, услуги и пакеты — на трёх языках и со ссылками на общие справочники. Сайт клиники, Symptex и партнёры (med24.uz, clinics.uz и другие) получают эти данные по ключу через API и присылают заявки и онлайн-записи, которые попадают в CRM с источником этого ключа. Документация API — внутри «Настроек».

## Решения владельца (2026-10-06)

1. **Пакет и личная скидка пациента — вариант A:** цена пакета окончательная; личные и категорийные скидки на пакет не действуют.
2. **Возврат одной услуги из пакета — вариант A:** остальные услуги остаются по цене пакета; пациенту возвращают цену возвращённой услуги в пакете.
3. **Карта пациента для записи от партнёра — вариант B:** заявка карту не создаёт; время держится без карты; регистратор выбирает или заводит карту, затем подтверждает.
4. **Лицензия не продлена — вариант B:** публичные данные и запись останавливаются (ответ 503) до продления.
5. **Ключи можно открыть и скопировать снова** (не «показать один раз»): хранятся зашифрованными, видят только администраторы, в журналы не пишутся.
6. **Справочники зашиты в программу, из medcore ничего не читается.** География (7 стран, 14 регионов, 206 районов с кодами и ru/uz/en — миграция 132, GEO_HARDCODE_V1) уже есть. Специальности — список `public/js/shared/specialty-list.js` (53), расширить ещё на 50+ (владелец: «add another 50+»). В формах — выпадающие списки, как при регистрации; партнёры получают коды (slug), а не текст.
7. Адрес API — `https://settings.easymed.uz/<клиника>/v1/` (как написал владелец; смена домена — отдельным словом владельца).

## Правила, без которых не строим (из проверки)

- **Документы печатают прежние имена.** Клиника — `doc_settings.clinic_name`, врач — `users.full_name`, специальность — `users.specialty` (русская). Названия на uz/en добавляются рядом и идут только наружу.
- **Логотип не прячет название.** Правило LOGO_WORDMARK_V1 (`shared/doc-render.js:477-481`) меняется до появления квадратного логотипа. Печать — только квадратный логотип; в PDF Telegram логотип встраивается.
- **Карточка сотрудника и «Мой профиль» — один профиль.** Каждый экран сохраняет только изменённые им поля; публикацию врача меняет только администратор.
- **Часы работы филиала.** Пусто = без ограничений (как сейчас). Перед сохранением экран показывает, каким врачам какое время закроется. Часы правит только главное здание.
- **Пакеты.** Одна общая функция раскладки скидки для расчёта, счёта, оплаты врача; цена пакета фиксируется на строке при записи; строки всегда дают ровно цену пакета (остаток округления — на последнюю, не ниже нуля). Пакет отличается от шаблона сметы отдельной отметкой.
- **CRM.** API-источники защищены как «Звонок»: сохранение списка источников их не удаляет и не переименовывает.
- **Онлайн-запись.** Только через ту же функцию записи, что у регистратора (`ensure_visit` / `calendar_book`); удержание времени 30 минут; ночной перевод в «Не пришёл» удержанные не трогает; наружу уходит только свободное время, без имён.
- **Сервер.** Очередь заявок — на отдельном публичном сервере в Узбекистане, не на сервере лицензий (там нет и не будет данных пациентов — проверяется тестом). Отправка — по образцу ретранслятора записей между зданиями, сбор — по образцу опроса телефонии.
- **Старое.** Экраны облачной эпохи «API», «Публичный сайт» и таблица-заглушка `api_tokens` убираются вместе с их тестами; по старому адресу `/api/v1` ничего не открывается.
- **Каждый шаг:** сначала тесты из списка «должно работать» своей области; весь набор тестов — в русской и английской среде; отдельная проверка, которая пытается сломать шаг; проба на тестовой клинике (:8712); выпуск только по слову владельца.

## Порядок (каждый шаг — свой план, свои метки, может выйти отдельно)

1. **Исправить 11 существующих ошибок** — `CLINIC_API_FIX_V1`.
2. **Справочники** — специальности 53 → 120 со слагами и ru/uz/en; экран «Справочники» (только просмотр) — `REFERENCE_LISTS_V1`.
3. **Профиль клиники и логотипы** — названия и описание на трёх языках; адрес главного здания выпадающими списками «Страна → Город / область → Район», как при регистрации пациента (коды из миграции 132), и улица на трёх языках (владелец, 2026-10-06: «в окне компании нет выбора географии»); два прозрачных PNG-логотипа (файлы, не data URL), сайт / Telegram / Instagram, карта и маршрут; правило «название рядом с логотипом»; Telegram. Прежнее текстовое поле `doc_settings.address` остаётся тем, что печатается в документах (собирается из выбранного, если клиника не правила его вручную — решить в плане шага).
4. **Филиалы** — название / улица / ориентир на трёх языках, город и район из справочника (коды), карта и маршрут, часы работы с предупреждением, «показывать на сайте»; синхронизация зданий.
5. **Публичный профиль врача** — переключатель публикации (админ), специальности по коду (до четырёх), языки приёма, фото для партнёров, цены консультаций, приём «по записи» / «живая очередь».
6. **Услуги и пакеты** — показ услуг по пяти группам; пакеты: отметка, имя на трёх языках, скидка процентом / суммой / ценой, общая раскладка, фиксация на строке, чек.
7. **Экран API, ключи, источники CRM** — подключения, ключи (генерация, копирование, шифрование), права, вебхуки, журнал; источник CRM на ключ; удаление старых экранов.
8. **Публичный сервер и онлайн-запись** — снимок наружу, очередь заявок, удержание и подтверждение (выбор карты регистратором), уведомления партнёрам, остановка при непродлённой лицензии.
9. **Документация API** — страница в «Настройках».

## Шаг 1 — существующие ошибки (CLINIC_API_FIX_V1)

| № | Ошибка | Что делаем |
|---|---|---|
| 1 | Сохранение карточки сотрудника стирает узбекские названия специальностей и код | `writeSpecialties` берёт slug / ru / uz из канонического списка; карточка отправляет специальности, только если их меняли |
| 2 | Карточка и «Мой профиль» затирают друг друга | Оба сохраняют только изменённые поля; RPC обновляет `updated_at` |
| 3 | «Ведёт» / «Бесплатно» в «Консультациях врачей» читаются неверно | Значения 0/1 из базы приводятся к логическим при чтении во всех трёх экранах |
| 4 | CRM показывает общую цену консультации, когда у врача своя | CRM берёт цену так же, как касса (`consultationFor`) |
| 5 | «Мой профиль» во втором здании затирается синхронизацией | Сохранение во втором здании отказывается с понятным сообщением (как карточка — 409) |
| 6 | CRM записывает на время врача с живой очередью | Для живой очереди CRM записывает без времени, как окно визита |
| 7 | В документах Telegram может быть старый логотип | Данные компании перекрывают сохранённую копию, как при печати из браузера |
| 8 | Название клиники под меню пустое после входа и не обновляется после «Компании» | Обновлять после входа и после сохранения |
| 9 | Импорт Excel включает «онлайн-запись» без узбекского названия | То же правило, что в окне услуги; нарушение — флаг не ставится, предупреждение в итогах импорта |
| 10 | Чек пишет «пакет "X"» для шаблона сметы без скидки | Подпись «пакет» — только при скидке больше нуля (до отметки пакета в шаге 6) |
| 11 | Проверка адреса фото врача не проверяет его собственную папку | Путь обязан лежать в `doctors/<id врача>/` |

Решение, которое ждёт владельца и в шаг 1 не входит: цена консультации врача без своей строки цены (касса берёт общую цену, окно записи консультацию скрывает).
