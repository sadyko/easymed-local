# CRM, календарь и регистрация — одна система (CRM_UNIFY_V1) — дизайн

**Дата:** 2026-10-09. **Статус:** согласован с владельцем (ответы 2026-10-09).

**Откуда:** сообщение владельца со скриншотами реальной клиники (≈45 000 пациентов, v3.16.x):
- «карточки CRM иногда пропадают»;
- «в конце колонок "Показать ещё 20" — убрать, чтобы все карточки были в окне»;
- «регистратор регистрирует пациента — карточка не переходит в конверсию, в "Пришёл" пусто»;
- «объединить календарь, CRM и регистрацию»;
- «операторы не видят свои задачи, нет фильтра по операторам».

Причины найдены чтением кода и воспроизведением на базе в памяти. Код этих мест одинаков в v3.16.0 и в текущей ветке.

## Что найдено (коротко)

1. **Карточку создают только три пути:**
   - звонок (`server/services/crm/lead-from-call.js`);
   - окно «Новая заявка»;
   - запись в календаре пользователем с ролью «только колл-центр» (`booking-mirror.js` `attachVisitToCrm`).

   Регистратор, администратор и врач карточку не создают и не находят. У пациента с визитом карточки может не быть вовсе: пример владельца, поиск 909092638.
2. **Доска грузит только 800 последних карточек** (`crm.js` `load`), это около двух недель звонков. Колонки показывают по 20 («Показать ещё»). Числа в заголовках считают только загруженное.
3. **Видимость.** Без права `crm.all` («Видит все заявки и передаёт их») сотрудник видит только свои и ничьи карточки, а поиск молча прячет чужие.
4. **Конверсия теряется:**
   - `calendar_book` не привязывает строки карточки к визиту, а дублирует их. Наутро обход переводит **оплатившего** пациента в «Не пришёл» (ошибка).
   - Оплата по другому визиту или по новой дублирующей карте пациента карточку не закрывает.
   - Привязка по телефону делается только в браузере, только для новой карты и в пределах видимости регистратора. Выбор существующей карты в быстрой регистрации не привязывает ничего.
5. **Колонку «записан» система угадывает:** сервер берёт «последнюю открытую по порядку», браузер — «первую видимую». У клиники записанные карточки уезжают в «Успешно».
6. **Задачи:**
   - Списка задач нет: задача видна только внутри своей карточки.
   - Когда карточку передают другому оператору, задача остаётся у прежнего: он видит её в красном счётчике, но открыть не может.
   - Администратор, создавая задачу на ничьей карточке, по умолчанию назначает её себе.
7. **Фильтра по оператору нет нигде.**

## Решения владельца (2026-10-09)

1. **Регистратор в CRM не работает.** Если пациент звонил или колл-центр его записал, а регистратор регистрирует этого пациента на стойке, карточка **сама** переходит в «Пришёл». Регистрация на стойке (быстрая регистрация, «пришёл без записи») = пациент пришёл.
2. **Пациент без карточки** (пришёл сам, регистратор записал напрямую) карточку **не получает**.
3. **«Пришёл» и «Отказ» — закрытые карточки, они не открываются заново.** Новая запись или новый звонок такого пациента после окна — **новая карточка** с тем же пациентом. Старая остаётся в «Пришёл» как история.
4. **Окно 72 часа** (настройка в «CRM-канбан», по умолчанию 72):
   - Звонок или новая запись в пределах окна от последнего движения карточки — та же карточка, без дублей.
   - После окна открытая карточка (например, три недели в «Перезвонить») **возвращается в «Новый лид»**: одна карточка, история внутри. Закрытая — новая карточка (п. 3).
   - Приход пациента на **уже назначенную** запись (записали за три недели) — это не новый контакт: карточка закрывается в «Пришёл» как обычно, окно здесь не действует.
5. **Застрявшие карточки исправить один раз при установке обновления:**
   - пациент оплатил или был зарегистрирован в день записи → «Пришёл», в том числе из ошибочного «Не пришёл»;
   - потерянные открытые задачи → текущему оператору карточки.

   Двигаются только однозначные случаи. Счета не меняются.

## Как будет работать

### Одна точка связи визита с CRM (сервер)
Один шаг на сервере после **любой** записи или регистрации:
- окно карточки «Записать на дату»;
- календарь и каталог услуг (`calendar_book`);
- быстрая регистрация и «пришёл без записи» (`ensure_visit`);
- добавление строк записи (`booking_lines_add`).

Он заменяет нынешние два разных пути (`settleCrmOnBooking` и `attachVisitToCrm`).

**Найти открытую карточку:**
- по карте пациента (`patient_id`);
- если такой нет — по телефону: открытая карточка **без пациента**, телефон совпадает (`phoneKey`), и **ровно у одной** карты пациента этот телефон.

  По телефону записывается только `patient_id`. Строки и счета от совпадения по телефону не трогаются: общий телефон в семье не должен перенести услуги на чужой счёт.

  Поиск идёт на сервере, вне видимости того, кто записывает. Ответ не раскрывает чужие карточки.

**Запись на будущий день** (колл-центр, календарь): строки этого дня привязываются к визиту (`visit_id`) **без дублей**, карточка переходит в колонку «записан».

**Регистрация на стойке** (визит сегодня, быстрая регистрация / «пришёл без записи»): карточка переходит в «Пришёл» сразу — решение 1. Оплата, начатая услуга и отметка «Пришёл» в календаре остаются доказательствами прихода, как сейчас.

При первом приходе карточка закрывается в «Пришёл» (решение 1). Строки на другие дни остаются в карточке и в календаре как записи.

**Пациент без карточки** — ничего не создаётся (решение 2). Исключение прежнее: запись пользователем «только колл-центр» создаёт карточку с источником «Звонок».

Окно 72 часа (решение 4) применяется в этом же шаге и при звонке (`lead-from-call.js`): одно правило, одна функция.

### Колонки
- **«Колонка записи» — явная настройка в «CRM-канбан».** Это открытая видимая колонка до «Пришёл». По умолчанию «Записан», если она есть и видна, иначе последняя открытая видимая колонка до «Пришёл». Одно правило для сервера и браузера.
- **«Не пришёл» ставит сервер:** запись прошла, визит не начат, не оплачен, не отмечен. Обход в браузере больше не решает и не трогает «Перезвонить» с прошедшей датой звонка.

### Доска
- «Показать ещё 20» убирается. Каждая колонка прокручивается внутри себя, страница не растягивается.
- **Загружаются все открытые карточки** (без предела 800); «Пришёл» и «Отказ» — за выбранный период. Числа в заголовках — настоящие итоги по базе в пределах видимости.
- **Фильтр «Оператор»:**
  - для руководителя (`crm.all`, администратор): Все / Мои / Ничьи / по имени;
  - для оператора: Все / Мои / Ничьи.

  Фильтр применяется при загрузке, в поиске, в «Списке», в выгрузке Excel и в «Отчёте».
- В «Списке» и Excel — колонка «Оператор».
- Поиск подсказывает «есть у другого оператора», если номер найден у чужой карточки. Саму карточку не показывает.

### Задачи
- Новый вид «Задачи» рядом с «Канбан / Список»:
  - группы: Просрочено / Сегодня / Позже / Без срока;
  - по умолчанию — мои; руководитель выбирает оператора;
  - строка открывает карточку.

  Красный счётчик открывает этот вид. Счётчик и список считают по одному правилу.
- **Задачи идут за карточкой.** При смене оператора карточки (взял, передали, объединили) открытые задачи прежнего оператора (или без исполнителя) переходят новому. Задачу, назначенную руководителем конкретному человеку, это не трогает.
- «Ответственный» по умолчанию — оператор карточки. У ничьей карточки выбор обязателен, «себе» по умолчанию больше нет. Выбирать можно только тех, кто видит карточку.
- На карточке доски чип задачи показывает, чья задача; своя задача — первой. В «Списке» есть колонка задачи.

## Правила, без которых не строим
- Деньги:
  - связь по телефону никогда не меняет строки, визиты и счета;
  - предоплата и визит на будущее не доказывают приход (как сейчас);
  - исправление прошлых карточек меняет только этап карточки и исполнителя задач.
- Видимость: серверный поиск карточки при записи не возвращает в ответе ничего о чужих карточках; права `crm.all` не расширяются.
- Синхронизация зданий: что едет и что не едет между зданиями — без изменений. Новый шаг работает в здании, где сделана запись.
- **Каждый шаг плана:**
  - сначала тест;
  - весь набор тестов в русской и английской среде;
  - отдельная проверка, которая пытается сломать результат;
  - проба на тестовой клинике (:8712);
  - выпуск — только по слову владельца.
- Новые тексты — ru / uz / en.

## Что не входит
- Карточки для пациентов, пришедших без звонка (решение 2).
- Единый RPC записи для всех окон (крупная переделка). Цель на потом; сейчас — одна общая точка связи после записи.
- Создание поставщиков из импорта закупок (отдельное решение владельца).
