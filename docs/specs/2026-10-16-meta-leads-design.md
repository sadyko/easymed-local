# Заявки из рекламы Meta в CRM и группа «Коммерческие инструменты» (META_LEADS_V1) — дизайн

Метки: `META_LEADS_V1` (всё вместе), подметки `…_HUB` (группа и плитка в настройках),
`…_STORE` (таблицы и шифрованный токен), `…_GRAPH` (клиент Graph API), `…_POLL` (опрос и
создание заявок), `…_VIEW` (экран настроек).

## Просьба владельца (2026-10-16)

Слова владельца: «I want to build Meta integration, and in setting block build separate
setting block of commercial instruments after salary of doctors, there start to build
integration, all the leads coming from meta ads should come to crm, so start it».

То есть:

1. в хабе «Настройки» после группы «Зарплата врача» появляется новая группа
   «Коммерческие инструменты»;
2. в ней — первый инструмент: интеграция с Meta (Facebook и Instagram);
3. каждая заявка из рекламы Meta (Lead Ads — форма, которую человек заполняет прямо в
   Facebook или Instagram) должна сама появляться в CRM клиники.

Сессия без ответов владельца: решения ниже приняты самостоятельно, проверяются на
dev-сервере до отправки, спорные места вынесены в «Вопросы владельцу».

## Главное архитектурное решение: клиника ОПРАШИВАЕТ Meta, а не Meta стучится в клинику

Meta умеет отдавать заявки двумя способами: присылать на публичный HTTPS-адрес (webhook)
или отдавать по запросу через Graph API. Easy-Med стоит на сервере клиники в локальной
сети: у него нет публичного адреса и сертификата, и делать их ради одной интеграции
нельзя — это ломает главное свойство системы (CLAUDE.md: «fully LOCAL»). Поэтому:

- сервер клиники сам ходит в `graph.facebook.com` раз в две минуты, пока интеграция
  включена, и забирает новые заявки. Нужен только исходящий интернет, как у Telegram-бота;
- интернета нет — заявки никуда не теряются: они ждут у Meta (хранятся 90 дней), а опрос
  заберёт их при следующем удачном соединении, потому что помнит, что уже забрал;
- webhook не строим. Вендорский control plane (`settings.easymed.uz/cp/`) теоретически мог
  бы принимать webhook и отдавать клинике при check-in, но check-in раз в сутки — для заявок
  это неприемлемо, а строить отдельную очередь ради этого рано. Записано в «Что не делаем».

## Что нужно от Meta (делает клиника один раз, по инструкции на экране)

1. Страница Facebook клиники и аккаунт Instagram, привязанный к ней, — уже есть, раз идёт
   реклама.
2. Приложение в developers.facebook.com (тип Business), добавлен продукт Marketing API /
   Lead Ads. Приложение остаётся в режиме разработки: для СВОЕЙ страницы право
   `leads_retrieval` действует без проверки Meta.
3. Токен доступа к странице, который не истекает: системный пользователь в Business
   Manager с правами на страницу и приложение → «Создать токен» с правами
   `leads_retrieval`, `pages_show_list`, `pages_read_engagement`, `pages_manage_ads`.
   Подойдёт и долгоживущий токен страницы (60 дней), но его придётся обновлять руками —
   экран предупреждает за 7 дней, если срок известен.
4. Для надёжной доставки заявок Meta также требует, чтобы у приложения был настроен
   приём событий `leadgen` (webhook). Мы его не настраиваем; при опросе это не обязательно,
   но в инструкции сказано, что если Meta потребует, можно указать любой адрес-заглушку.

Версия Graph API: `v26.0` (актуальная на 2026-07-29 по журналу изменений Meta). Одна
константа в клиенте; версия живёт не меньше двух лет, а при истечении Meta сама
перенаправляет на следующую — вызовы не падают.

## Решения

| Вопрос | Решение |
|---|---|
| Где в настройках | Новая группа «Коммерческие инструменты» (значок Megaphone) ПОСЛЕ «Зарплата врача», в ней плитка «Meta: заявки из рекламы» → маршрут `meta-settings`. Группа заведена так, чтобы следующие инструменты (Google Ads, Яндекс и т. п.) добавлялись плитками, а не группами |
| Кто видит | Своя строка в «Ролях» — `settings.meta` (группа «Коммерческие инструменты», уровни Нет / Просмотр / Изменение, правило «только администратор» для ненастроенной роли — как у Telegram-бота и Телефонии, потому что токен открывает заявки всей страницы). Экран лицензией НЕ закрыт (как `crm-settings`), чтобы не трогать `LICENSED_NAV_IDS`; модуль `crm` проверяет опрос каждым проходом (как телефония — `callcenter`), а экран без модуля показывает предупреждение «Модуль CRM не подключён» |
| Токен и ключ шифрования | Не `telegram/crypto.js`, а новее — `api/secret-box.js` (`loadKek` / `seal` / `unseal`): тот же ключ клиники, что у ключей подключений API, копия `.bak`, версия печати. Колонки `token_sealed` + `token_tail`, и отдельно `page_token_sealed` — токен страницы из `/me/accounts`, которым читаются формы и заявки (право `leads_retrieval` действует на страницу). Вставленный напрямую токен страницы — сам себе страница |
| Много заявок за раз | За проход — до 50 страниц по 100 заявок на форму. Больше — только при первом заборе истории у очень большого аккаунта: берутся самые свежие, курсор двигается, в `last_error` — слово `truncated`, экран объясняет и предлагает «Забрать за N дней» |
| Как заявка попадает в CRM | Тем же путём, что заявка партнёра из API (`api/bookings.js` createCard), а не как звонок: прямой INSERT в `crm_requests` с именем, телефоном в формате клиники (`uzE164`), источником и списком источников (`source` + `sources`), первой открытой колонкой (`firstStageKey`) и комментарием. Путь звонка (`lead-from-call.js`) привязан к исходам звонков и маршрутизации — не подходит |
| Источник | Ключ `meta_ads`, подпись «Meta (Facebook / Instagram)» в словаре `crm_sources`; создаётся при первой заявке, выключенный — включается обратно; добавлен в `UNDELETABLE_SOURCE_KEYS` (сервер и клиентское зеркало), иначе удаление источника ломало бы каждую следующую заявку ошибкой внешнего ключа |
| Что пишем в заявку | Имя (`full_name`, иначе имя + фамилия, иначе e-mail, телефон или «Заявка Meta»), телефон, e-mail, и в комментарий — шапка «Заявка из рекламы Meta (Instagram) · дата», строка «Форма · Кампания · Объявление», e-mail и все остальные ответы формы построчно «Вопрос: ответ» (имена полей Meta вида `какая_услуга?` → «Какая услуга?»). Регистратура видит, на что человек откликнулся |
| Повторы | Два разных вопроса. Та же заявка Meta (`leadgen_id`) второй раз — журнал `meta_leads` держит его уникальным, вторая карточка невозможна по построению. Тот же человек (телефон) — правило окна повторного обращения CRM (`contactDecision`, как у входящего звонка): открытая карточка получает ответы формы в комментарий и источник Meta в список источников вместо второй карточки; карточку, которую пора вернуть, — возвращаем в первую колонку. Отличие от звонка одно: «закрыта только что» для формы — новая карточка, а не молчание: человек сам написал заявку, доска подсветит дубликат по телефону |
| Какие формы | По умолчанию — все формы страницы; на экране можно снять галочки с ненужных. Новые формы, появившиеся у страницы позже, подхватываются сами, если не выбран режим «только отмеченные» |
| Частота опроса | Каждые 2 минуты, пока включено; кнопка «Проверить сейчас» на экране. Лимит Meta — 200 × 24 × (заявок за 90 дней) запросов в сутки на страницу, нам хватает с запасом |
| С какого момента | С момента включения (не тянем историю за 90 дней без спроса). На экране есть «Забрать заявки за последние N дней» для первого запуска |
| Токен | Хранится на сервере зашифрованным, как токен Telegram-бота; в браузер не возвращается — только признак «токен задан» и дата проверки. Ввод — одно поле, кнопка «Проверить связь» показывает имя страницы и число форм |
| Ошибки | Последняя ошибка опроса видна на экране человеческим языком (токен истёк / нет прав / нет интернета), и в строке плитки хаба. Опрос не останавливается из-за ошибки, кроме «токен недействителен» — тогда выключается до нового токена, чтобы не долбить Meta |
| Интернета нет | Обычное состояние клиники. Опрос молча ждёт следующего раза; на экране — «последняя удачная проверка: …» |
| Что не меняется | CRM-канбан, его этапы, права, экран телефонии. Схема существующих таблиц не трогается — новые таблицы рядом |

## Экран «Meta: заявки из рекламы» (`public/js/admin/views/meta-settings.js`)

Строится по образцу `telegram-settings.js` (карточки, кнопки «одна за раз», карточка-инструкция):

1. **Подключение** — поле токена (пустое, с подписью «токен задан, проверен 16.10 14:02»),
   кнопки «Проверить связь» и «Сохранить»; после проверки — имя страницы, её id, список
   форм с галочками и числом заявок у каждой.
2. **Опрос** — переключатель «Забирать заявки», период опроса (2 мин по умолчанию), «Проверить
   сейчас», «Забрать за последние N дней»; строка состояния: последняя удачная проверка,
   последняя ошибка, сколько заявок получено сегодня и всего.
3. **Последние заявки** — таблица 50 последних: дата по Meta, имя, телефон, форма, статус
   (создана заявка CRM / присоединена к открытой / ошибка), ссылка на карточку в CRM.
4. **Как получить токен** — пошаговая инструкция, как у Telegram, с предупреждением о
   бережном хранении токена.

## Данные (миграция `246_meta_leads.sql`)

- `meta_settings` — одна строка (`id = 1`): `enabled`, `page_id`, `page_name`,
  `token_enc` (шифртекст, никогда не отдаётся через /api/db — таблица НЕ попадает в
  schema-registry, только RPC), `token_checked_at`, `token_expires_at`,
  `forms_mode` ('all' | 'selected'), `forms_json` (список форм с id, name, selected),
  `poll_minutes`, `since_ts` (с какого времени забирать), `last_poll_at`, `last_ok_at`,
  `last_error`, `source_id` (ссылка на источник CRM), `updated_at`.
- `meta_leads` — журнал: `leadgen_id` UNIQUE, `form_id`, `form_name`, `ad_id`, `ad_name`,
  `campaign_id`, `campaign_name`, `platform`, `created_time` (по Meta), `field_data_json`,
  `phone`, `full_name`, `email`, `crm_lead_id`, `status` ('created' | 'merged' | 'error'),
  `error`, `received_at`.
- Сырые ответы формы — персональные данные пациента: таблица живёт в той же базе клиники и
  никуда не уходит (статистика `ops_events` по-прежнему без свободного текста: считаем только
  количества).

## RPC (`server/services/rpc/meta.js`) — как построено

- `meta_settings_get` → всё, кроме токена; `token_set`, хвост — только администратору.
- `meta_settings_save({ enabled, poll_minutes, forms_mode, forms })` — заплатка; будит опрос.
- `meta_connect({ token?, page_id? })` → `/me`, `/me/accounts`, `/{page}/leadgen_forms`;
  без `token` — сохранённым (повторная проверка, смена страницы). Отказ Meta — `ok:false`
  с причиной и фразой, не исключение: прежнее подключение остаётся.
- `meta_token_clear()` → стирает токены, страницу и формы, выключает опрос; журнал цел.
- `meta_poll_now({ days? })` → один проход сейчас; `days` сдвигает `since_ts` назад (1–90);
  ответ — настройки и сколько заявок принёс проход.
- `meta_leads_recent({ limit })` → журнал для таблицы с этапом карточки CRM.

Все — `grantAllowsAdminOr(db, user, 'settings.meta', …)`: чтение — «Просмотр», остальное —
«Изменение». Обычный 402-гейт лицензии, как у телефонии.

## Опрос (`server/services/meta/poller.js`)

1. Старт вместе с сервером, как остальные фоновые задачи (образец — после обзора кода);
   под тестами не запускается.
2. Каждый проход: если `enabled` и токен есть — для каждой выбранной формы
   `GET /{form_id}/leads?fields=id,created_time,field_data,ad_id,ad_name,campaign_id,campaign_name,platform&filtering=[{"field":"time_created","operator":"GREATER_THAN","value":since}]`
   с постраничным обходом; каждую заявку с новым `leadgen_id` — в `meta_leads` и в CRM;
   `since_ts` = максимум `created_time` из увиденного.
3. Ошибка сети — `last_error`, следующий проход по расписанию. Ошибка токена (код 190) —
   `enabled = 0`, `last_error` человеческим языком, плитка хаба показывает «нужен новый токен».
4. Из одной заявки Meta: имя — поле `full_name` (или `first_name` + `last_name`), телефон —
   `phone_number` (нормализуется, как телефон из звонка), e-mail — `email`; остальные
   вопросы — в комментарий.

## Клиент Graph API (`server/services/meta/graph.js`)

Тонкая обёртка над `fetch` с таймаутом: `graphGet(path, params, token)` → JSON или ошибка с
кодом Meta (`error.code`, `error.error_subcode`, `fbtrace_id`) и нашим переводом на человеческий.
Тесты подменяют `fetch`.

## Что не делаем сейчас

- Webhook от Meta (нет публичного адреса у клиники — см. выше).
- Сообщения Instagram Direct, WhatsApp Business, Messenger — другие продукты Meta.
- Статистика расходов на рекламу, окупаемость кампаний — отдельная задача «Коммерческие
  инструменты → Отчёты», когда появятся данные.
- Google Ads и другие источники — следующие плитки той же группы.
