### Бланк диагностики

- **Шапка.** Шаблоны читают `d.study.kind` и `d.study.area` (DV:807, DV:859). Объект `study` не строит ни один код (есть только в образце, DV:393). Данные бланка несут `service` (WS:4766, 4817-4824, 4436-4442, 3792-3799), но шаблон его не читает. Поэтому у КАЖДОЙ диагностической услуги «Исследование» и «Область» — «—»: на экране, на бумаге и в архиве.
- **«Описание» теряется.** Формы под бланком нет поля `instrumental_text` (WS:1017-1056; `DOC_SECTIONS` WS:2825-2840), `_syncBlankField` (WS:5145) писать некуда. Описание не сохраняется, не печатается и не попадает в архив.
- **Набранное «Заключение» пропадает.** Оно уходит в `primary_diagnosis` раздела «Диагноз». Этот раздел свёрнут по умолчанию (WS:2841), а `collectFields` пропускает свёрнутые (WS:2237). Остаётся, только если выбран код МКБ-10.
- **Чужой пациент на бумаге.** Если оба поля пусты, печать получает данные без `__editor`, и DV:283 печатает образец «Рахимов Жасур / МРТ головного мозга».
- **Подпись.** «Врач-рентгенолог» зашит в DV:848 и DV:892 — и для УЗИ тоже.
- **Тип бланка.** «Диагностика» включается сама только при `departments.kind='diagnostics'` (WS:187). У диагностических услуг клиники отделения нет, поэтому врач всегда выбирает тип вручную.

## 1. Журнал услуг — «не выбрано» значит «все» (`JOURNALS_V1_ALL`)

**Сервер.** `service_journal` без `service_ids` (пусто или только мусор) строится по ВСЕМ услугам. Отказа «Выберите услуги» больше нет. Предел 2000 остаётся только для явно выбранных.

**Экран.**
- Кнопка показывает «Все услуги», пока ничего не выбрано, и «Выбрано услуг: N», когда выбраны.
- Подсказки «Выберите услуги» нет.
- Запомненный выбор — как сейчас.
- Заметка отчёта говорит, по каким услугам он построен: «все услуги» или «выбрано N».

**Тесты.** Пустой выбор → все строки; неверные id → все; правило для явно выбранных — прежнее.

## 2. Бланк диагностики показывает услугу (`CABINET_FIX_V1_DIAG`)

**Шапка и карточка.**
- DV:807 и DV:859: `const st = Object.assign({ kind: d.service || '' }, d.study || {});` — «Исследование» берётся из названия услуги. Это сразу чинит экран, печать и уже подписанные документы: в архивном теле есть `service`.
- «Область»: если значения нет, поле в шапке скрывается, а не показывается «—».
- Карточка «Исследование» (DV:842) показывается, только если есть «Аппарат» или «Протокол».

**Тип бланка.** Услуга с `services.type = 'imaging'` (или с видом услуги «Диагностика») открывает бланк «Диагностика» сама (WS:187). Врач может переключить вручную, как сейчас.

**Подпись.** Вместо зашитого «Врач-рентгенолог» — основная специальность врача (из карточки сотрудника); если её нет — «Врач».

**«Описание» и «Заключение» не теряются.**
- У бланка диагностики «Описание» (`instrumental_text`) и «Заключение» (`primary_diagnosis` или собственное поле заключения диагностики — выбрать по коду, лишь бы одно) сохраняются, печатаются и попадают в архив ВСЕГДА, независимо от того, свёрнут ли раздел.
- Решение — завести поля в данных документа так, чтобы `collectFields` собирал их у диагностики всегда.

**Никогда не печатать образец.** Если данные пусты, печатается пустой бланк этого пациента, а не «Рахимов Жасур».

**Тесты.**
- Название услуги в шапке: на экране, в печати и в архивном теле.
- Описание и заключение после сохранения, перезагрузки и печати.
- Пустой бланк — без образца.
- Подпись по специальности.
- Автоматический выбор «Диагностики».

| Буква | Исправление |

**Тесты.** Сервер (правило личного, `doc_type` строкой) и экран (вставка шаблона диагностики, редактор «Документов»).

## 4. Рецепты — шаблоны и «свои» препараты (`RX_TEMPLATES_V1`)

**Шаблон целого рецепта.**
- Без миграции: `consultation_templates` с `doc_type '3'` («Рецепт»), `body = { rx: [{name, dose, freq, dur, notes, nurse}] }`.
- В окне «Новый рецепт» две кнопки:
  - «Из шаблона» — список шаблонов-рецептов (мои + общие клиники); выбор добавляет все препараты строками;
  - «Сохранить как шаблон» — название и «Личный / Общий».
- Правила личного — как в п. 3.C.
- Шаблоны рецептов не показываются среди шаблонов документов, и наоборот.

**«Свои» препараты — подсказки при вводе названия.** Источники подсказок, по порядку:
1. препараты из рецептов, которые этот врач уже сохранял (с дозой, частотой и длительностью; самые частые — первыми);
2. препараты из его шаблонов рецептов;
3. справочник клиники (`products.is_drug = 1`, только название).

Выбор подсказки заполняет дозу, частоту и длительность (их можно поправить).

Список «своих» складывается сам из работы врача — отдельного экрана для его ведения нет. Источник 1 — новый RPC только для чтения `rx_my_drugs` (по `visit_services.doctor_id = я`, разбор `notes.prescriptions`, до 200 строк). Права: врач или администратор.

**Тесты.** Сохранение и вставка шаблона-рецепта; личный шаблон не виден другому врачу; `rx_my_drugs` — только мои, частые первыми, не больше предела; подсказки на экране.

## 5. Печать в один шаг (`PRINT_AUTO_V1`)

- `printableSheet` (DS:190-196): если в HTML нет `window.print`, добавить перед `</body>` скрипт печати при загрузке, как в рабочих окнах. После печати окно закрывается (`onafterprint`).
- То же для чеков кассы (`receipt-print.js:126, 244, 339`) — одним общим помощником.
- Предпросмотр в «Документах» и PDF для Telegram скрипты уже вырезают (DOCS:692, `telegram/render.js:54-55`). Проверить, что так и остаётся.
- Chrome помнит последний принтер: врач жмёт «Печать», затем Enter.

**Тесты.** HTML печати содержит скрипт ровно один раз; предпросмотр и Telegram — без скрипта.
