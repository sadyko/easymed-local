# Список анализаторов: в «Добавить прибор» — только выходившие на связь (LIS_ANALYZER_LIST_V1) — дизайн

**Статус:** утверждено владельцем 2026-09-29 («Yes, go ahead»).
**Уточняет:** LIS_AUTODISCOVER_V1 (миграция 124). Решение «we should not setup anything» остаётся: анализатор по-прежнему появляется сам, но теперь в окне «Добавить прибор», и в таблицу его переводит одно нажатие.

---

## Просьба владельца (дословно, 2026-09-28)

> We need to make list of the analyzers when adding a dynamic list, which will be empty if analyzer not plugged or connected and we see in the adding list an analyzer if we are activated, now there is several analyzers list when adding a analyzer (which shouldn't be there if its not connected)

## Решения владельца

1. **Какой список** (2026-09-28): окно «Добавить прибор». В нём только анализаторы, которые действительно присылали что-то в Easy-Med. Если ничего не подключено, окно пусто и объясняет, как подключить. Маленькая ссылка «добавить по адресу» остаётся для приборов, которые не могут выйти на связь сами.
2. **Таблица** (2026-09-28): показывает только анализаторы, которые что-то присылали. Добавленные руками появляются в ней, когда выйдут на связь.
3. **Найденный — одно нажатие** (2026-09-29): новый найденный прибор не попадает в таблицу сам. Он ждёт в «Добавить прибор» одного нажатия, а его результаты тем временем сохраняются.

---

## Как сейчас (проверено 2026-09-28 на базе разработки)

- **Список моделей.** «Добавить прибор» открывает форму с выпадающим «Модель» из шести профилей Mindray. Список один и тот же, есть эти приборы в клинике или нет. Это и есть «several analyzers list» из просьбы.
- **Найденный прибор** (`discovered = 1`) сразу стоит в таблице.
- **Добавленные руками без адреса стоят в таблице, даже если молчат.** «jjjj» добавлен 28.09 и ни разу не выходил на связь.
  - Два таких прибора ломают правило «единственный прибор без адреса — он и есть отправитель» (`discover.js`, шаг 3).
  - Поэтому следующая проба симулятора завела третью строку. Так 28.09 появился «BC-5300».
- **«На связи» врёт о молчании.** `last_seen_at` ставится, только когда проба легла в бланк или пришла как `superseded`. Сообщение, не нашедшее заказ, прибор не отмечает. «kjkj» показывал «молчит с 10.09», хотя присылал пробы до 14.09.

## Три состояния прибора

| Состояние | Условие | Где видно |
|---|---|---|
| найден, не добавлен | `added = 0` | «Добавить прибор» → «Найдены в сети» |
| добавлен, ждёт первого сообщения | `added = 1`, `last_seen_at` пуст | «Добавить прибор» → «Ждут первого сообщения» |
| добавлен и выходил на связь | `added = 1`, `last_seen_at` есть | таблица «Анализаторы» |

Приём от состояния не зависит. Результаты найденного, но не добавленного прибора сохраняются и применяются по тем же правилам: привязка панели и правило «та же модель» (`ingest.js`). Ждать нажатия может только место прибора на экране, а не пробы пациентов.

---

## Схема — миграция `228_lab_device_added.sql`

- `ALTER TABLE lab_devices ADD COLUMN added INTEGER NOT NULL DEFAULT 1`. Все существующие строки остаются добавленными, и найденные раньше, и заведённые руками. Из таблицы уходят только те, кто ни разу не выходил на связь.
- **Бэкфилл «на связи».** `last_seen_at` = самое позднее `received_at` сообщений этого прибора — там, где оно позже текущего или текущее пусто. Так исправляется прошлое вранье о молчании.
- **Повторный накат** ничего не меняет.
- **Реестр схемы:** `added` добавить в чтение и в `update` — добавление найденного и есть `update added = 1`. `insert` колонку не получает: по умолчанию 1, всё, что заводит человек, уже добавлено.

## Сервер

1. `discover.js` → `ensureDevice`: новая находка заводится с `added = 0`. Остальное не меняется: поиск по адресу, модели и имени, потолок в 20 находок.
2. **«На связи» — на любом разобранном сообщении.** `ingest.js` отмечает известный прибор (`touchDevice`) после успешного разбора, чем бы ни кончилось: `unmatched`, `unmapped`, `applied`, `superseded`. Мусор (`rejected`) прибор не отмечает: неразобранное не доказывает, что это анализатор.
3. **RPC `lis_listeners`.**
   - Что отдаёт: какие порты слушаются прямо сейчас, из `server/lis/index.js`.
   - Только чтение; роли — как у остальных RPC лаборатории; внесён в `READ_ONLY_RPCS`.
   - Нужен для честной строки у ждущих приборов: «порт 2575 слушается» или «порт 5100 не слушается — возможно, его заняла другая программа». Это и есть проверка связи с нашей стороны.

## Экран «Анализаторы»

- **Таблица** — только `added = 1` и `last_seen_at` есть. Если пусто: «Подключённых анализаторов нет» и подсказка открыть «Добавить прибор».
- **Кнопка «Добавить прибор»** показывает число найденных, если они есть.
- **Окно «Добавить прибор»** вместо формы с моделями:
  1. **«Найдены в сети»** (`added = 0`).
     - В строке: имя, которым прибор назвал себя; модель (догадка по имени, иначе «модель не определена»); адрес; когда присылал в последний раз.
     - «Добавить» открывает короткую форму: название подставлено, модель выбрана по догадке, но её можно поменять. «Сохранить» ставит `added = 1`, и прибор в таблице.
     - «Удалить» — для ошибочных находок.
  2. **Пусто** — «Ни один анализатор пока не выходил на связь.» и как подключить: адрес этого компьютера, порт 2575, протокол HL7, отправить пробу.
  3. **«Ждут первого сообщения»** (`added = 1`, ни разу не выходили на связь): название, адрес и порт, строка о порте из `lis_listeners`; «Изменить» и «Удалить».
  4. **Ссылка «Анализатор не появился? Добавить по адресу»** открывает прежнюю форму: название, модель, подключение, адрес, порт. Там честная строка: анализаторы, которые сами ждут звонка от программы LIS (например, Mindray BC-3600), пока не поддерживаются.
- **Правка строки таблицы** — как сейчас, форма «Изменить».

## Панели

«Анализатор» у панели: только добавленные (`added = 1`) плюс прибор, к которому панель уже привязана. Ничего не ломается, а ненажатая находка не выглядит как выбранный прибор.

## Что НЕ меняется

- **Инварианты приёма:** D4 (только подтверждённые сопоставления), инвариант 1 (нет автовыдачи), D7 (`superseded`), инвариант 2 (сообщение целиком).
- **Самоопределение** (`discover.js`), кроме `added = 0` у новой находки.
- **Правило лотка** из LIS_MINDRAY_CODES_V1.
- **Прибор-сервер** (второй тип подключения: программа LIS звонит прибору, как у BC-3600) не строится. Поле направления подключения можно добавить позже, этот дизайн ему не мешает.

## Ревью 2026-09-29

Решения владельца не менялись. Правки — по находкам ревью.

- **`discovered` — только у сервера (C1).** Это правило приёма, а не пометка: `discover.js` не сверяет модель у строки с `discovered = 0` («заведён человеком на этот адрес»). «Добавить» писал `discovered = 0`, и после одного нажатия всё, что шлёт с того же адреса (переадресаторы COM на одном ПК, 127.0.0.1, симулятор), ложилось в добавленную строку. Теперь «Добавить» пишет `name`, `added = 1` и модель, если она выбрана. `discovered` снят с `update` в реестре схемы.
- **Пометка «найден сам — проверьте модель» — колонка `model_confirmed`** (в той же миграции 228, по умолчанию 0; приём её не читает). Её ставят «Добавить» и «Изменить» найденного прибора с выбранной моделью. Пометка в таблице видна, только пока `discovered = 1` и `model_confirmed = 0`. Раньше она висела вечно: `discovered` трогать нельзя, а своего признака не было.
- **Удаление прибора — RPC `lis_device_delete` (C2).** Голый DELETE через `/api/db` упирался во внешние ключи сообщений и панелей (мигр. 123) и не удалял ни одну находку.
  - Прибор у панели (любой, и выключенной) — отказ 409 с названиями панелей: «Прибор привязан к панелям: … — сначала выберите у них другой анализатор.»
  - Иначе одной транзакцией: сообщения отвязываются (`device_id = NULL`, текст целиком, инвариант 2), строка прибора удаляется. Потом слушатели перезапускаются, как `lis_restart`.
  - Роли — как у остальных RPC лаборатории. Это запись, поэтому RPC не в `READ_ONLY_RPCS`.
- **Пустое окно «Добавить прибор» (I1).** Если список не прочитался — ошибка чтения. Если находок нет, но в таблице или среди ждущих кто-то есть — «Новых анализаторов пока нет.» и как подключить. «Ни один анализатор пока не выходил на связь.» — только когда пусто всё.
- **Модель (I2).** «Добавить» с «модель не определена» не пишет модель вовсе, и догадка сервера остаётся. Это же спасает, когда `lis_profiles` не ответил. В «Изменить» первый пункт — «модель не выбрана». Модель без профиля — своим пунктом. Новый прибор по адресу по-прежнему начинает с первой модели.
- **«На связи» и ручная привязка (M4).** `ingestMessage(…, { touch: false })` — привязка из лотка прогоняет старое сообщение, и отметку связи не ставит: нажал человек, а не заговорил прибор.
- **Порты (M5, M6).**
  - Не поднявшийся порт — кодом: `busy` (порт занят) или `error`. Экран пишет «порт N занят другой программой» или «порт N не слушается». Сырой текст сервера на экран не попадает.
  - Строка о порте у ждущего — только для сетевого прибора. У выключенного — «выключен».
- **Миграция 228 (M7).**
  - Бэкфилл одним проходом (`UPDATE … FROM` с `GROUP BY`). Мусор (`rejected`) не в счёт. Метка из будущего не копируется. Повторный накат ничего не меняет.
  - Индекс `idx_lab_device_messages_device (device_id, id)` — для бэкфилла, удаления прибора и `lis_device_codes`.
- **Экран (M1, M2, M3, M9).**
  - Подсказка под «Анализатор» у панели — по тому же списку, что и выбор.
  - Инструкция ведёт в «Добавить прибор» → «Найдены в сети» → «Добавить».
  - Правка и удаление из окна «Добавить прибор» возвращают в окно.
  - Живой опрос перерисовывает окно, только когда изменилось видимое.

### Известные ограничения

- **M8 — «единственный прибор без адреса — он и есть отправитель»** (`discover.js`, шаг 3; было до этой задачи, не менялось). Прибор, добавленный руками без адреса и ни разу не выходивший на связь, забирает сообщения с любого незнакомого адреса, какой бы модели ни был отправитель. Два таких прибора выключают правило, и следующая проба заводит новую находку — так 28.09 появился «BC-5300». Лечение — адрес у каждого прибора, заведённого руками.
- **Смена модели при «Добавить».** Правило «та же модель» (`discover.js`, шаг 1) сверяет догадку по имени с профилем строки. Если при «Добавить» заменить угаданную модель другой, следующая проба того же прибора заведёт новую находку («BC-5300 (127.0.0.1)»). Если оставить догадку, приём не меняется.
- **M11 — запасной путь для старого сервера у «Панелей» не срабатывает.** `lab-panels.js` просит колонку `added` по имени, и сервер без миграции 228 ответит на такой запрос 400, так что ветка `d.added == null` там не выполнится. Вреда нет: экраны поставляются вместе со своим сервером.
- **`lab-devices-lists.js`** подключается со штампом `?v=lists2`: модуль уже менялся (коды портов), а старая копия в кэше браузера показала бы порт без причины.
