# Выпуск 3.21.0 — одиннадцать исправлений после 3.20.0 (2026-11-02)

Владелец прислал список после выпуска 3.20.0 (выпуск партнёра, 918df28c; полный прогон
на нём: 12 743 теста, 0 падений). Шесть исследований (только чтение, копии баз, без
данных пациентов) нашли причины; ниже — причина, решение владельца и как будет.
Ветка `rc/3.21.0` в easymed.api5 от 918df28c.

## Решения владельца (2026-11-02)

1. У врача нет свободного времени сегодня (вечер, выходной, всё занято) — регистратор
   **сам выбирает день**: система показывает «Ближайшее: вт 3 ноября 09:00», молча на
   другой день ничего не ставит.
2. Услуги, добавленные, пока счёт пациента не оплачен, — **в тот же неоплаченный счёт**
   (тот же номер, новая сумма). Счета плательщику, оплаченные и стационарные — никогда.
3. Жёсткий запрет повторного направления — **в пределах одного визита**.
4. Бонус за направление — **обоим**: партнёр, приведший пациента, получает своё, а врач,
   направивший на услугу, — свою ставку за строки, на которые он направил.

Решения по умолчанию, объявленные владельцу (он не возразил): в печати — день приёма;
«Тип визита» — настоящий; «Последний визит» — последний состоявшийся (≤ сегодня) и
отдельной строкой ближайшая запись; отменённые и «не пришёл» не считаются; сохранённый,
но не завершённый приём остаётся «Идёт приём», незавершённые прошлых дней — в свёрнутой
группе; регистратор видит, КОМУ бонус, но не сумму; смену логина делает только
администратор и не при подключённых филиалах; сброс пароля снимает блокировку входа;
этикетка — на каждую пробирку.

## U1. Дата в печати протокола (PRINT_VISIT_DATE_V1)

**Сегодня.** `service-workspace.js` `buildBlankData` (~:6497) ставит `issueDate: new Date()`
— экран, «Печать» и архивная копия при подписи получают день печати/подписи.
Шаблоны (`doc-variants.js` ~:669 «Дата приёма», ~:782 «от …»). Диагностика
(`imagingClassic`/`imagingCompact`, ~:1003/:1059) читает `d.dateOut || today`, а
`diagDocData` (~:6545) `dateOut` не ставит — любой лист диагностики, и перепечатка из
архива (`patient-card.js` ~:1539), датирован сегодняшним днём. «Тип визита» всегда
«Первичный приём» — `visitType` не задаётся.

**Как будет.**
- Одна функция «день документа»: местный день `ctx.patient.__service.visitDate`
  (`visits.visit_date`, ISO UTC → местная дата, не `slice(0,10)`), иначе первая
  подпись `savedAt`, иначе сегодня. `buildBlankData.issueDate` и `diagDocData.dateOut`
  берут её.
- Шаблоны диагностики: `d.dateOut || d.issueDate || today` — старые архивные листы
  без `dateOut` печатают свою `issueDate` без миграции.
- «Тип визита» — по `price_tier` строки (первичный/повторный/…); нет данных — строки нет.

**Тесты.** Приём 3 дня назад печатает тот день (заключение и диагностика); архивный лист
без `dateOut` печатает `issueDate`; визит в 00:30 местного (прошлый день UTC) — местный день.

**Сегодня.** Список «Мои приёмы» (`consultation.js`) — единственный вход в
`#service-workspace`. Фильтр «Активные» верный, но экран кэшируется (`admin.js` ~:606-660:

очереди нет. Незавершённые строки прошлых дней не уходят (диапазон по умолчанию 'all').

**Как будет.**
- После подписи строка сразу локально `completed`, и список перезагружается при
  возвращении (флаг «очередь устарела», который проверяет экран; общий хук «при показе»

- «Сохранить» без «Завершить приём» — строка остаётся «Идёт приём» сверху.
- Незавершённые строки прошлых дней — внизу «Активных» свёрнутой группой
  «Незавершённые с прошлых дней · N».
- «Мой день»: завершённые визиты сразу уходят в «Завершённые · N».

**Тесты.** После подписи строка в «Завершённые», не в «Активные»; «Обновить» не
сбрасывает фильтр; прошлые незавершённые — в свёрнутой группе.

## U4. Администратор меняет логин, данные и пароль сотрудника (STAFF_EDIT_V1)

**Сегодня** (3.20.0 эти файлы не трогал).
- Логин: поле заблокировано при правке (`employees.js` ~:976 `disabled: isEdit`), PATCH
  его не шлёт (~:1173), сервер не читает (`routes/users.js` ~:747, UPDATE ~:846-854) —
  200 и ничего не меняется.
- Данные сохраняются, но карточка шлёт ВСЕ поля (~:1114-1143), сервер заново проверяет
  каждое (~:67-101) — одно старое неверное значение (дата «15.01.2020», категория)
  блокирует сохранение посторонним сообщением.
- Пароль меняется, но: блокировка входа (5 ошибок → 5 минут, ключ `имя|ip`,
  `services/auth.js` ~:104-108) переживает сброс администратором — сотрудник, забывший
  пароль, получает 429 с новым паролем; сброс отключённому сотруднику говорит «изменён»,
  а войти нельзя. Поле «Новый пароль» в СВОЕЙ карточке администратора меняет пароль без
  текущего; у поля нет `autocomplete="new-password"`.

**Как будет.**
- Логин меняет только администратор (не «вход как сотрудник»): сервер — trim + нижний
  регистр, то же правило, что при создании (~:685), проверка занятости
  `username = ? COLLATE NOCASE AND id <> ?`, ошибка UNIQUE → 400 «Такой логин уже занят.»,
  смена только регистра — ничего не делает. При подключённых филиалах — отказ 409
  «Логин нельзя менять, пока подключены филиалы: филиалы узнают сотрудника по логину.»
  Открытые сеансы сотрудника остаются. Карточка: поле доступно администратору, `username`
  уходит только если изменён, отказ — под полем.
- Карточка шлёт только изменённые поля; сервер не проверяет значения, равные
  сохранённым.
- Любая установка пароля (сброс и своя смена) снимает блокировку входа этого логина
  (`clearLoginLocks(username)` в `services/auth.js`). Отключённому — ответ с признаком,
  экран: «Пароль изменён, но сотрудник отключён — включите «Активен», иначе он не войдёт.»
- В своей карточке поля «Новый пароль» нет (кнопка «Сменить пароль» спрашивает текущий);
  `autocomplete="new-password"`.
- Выбор «Врачи» в «Должности» на карточке администратора не снимает роль администратора
  (ставит признак врача, ADMIN_DOCTOR_V1).

**Тесты** (`users.test.js`, `employees-card-save.test.mjs`): смена логина — новый входит,
старый 401; занятый в другом регистре/с пробелами → 400; неверный → 400; только регистр —
без изменений; не администратор → 403; филиалы → 409; «вход как» → отказ; 5 ошибок →
сброс → вход 200; отключённый → признак; старое неверное значение не мешает сменить
телефон; своя карточка без поля пароля.

## U6. Новые услуги — в неоплаченный счёт (INVOICE_APPEND_V1)

**Сегодня.** Каждый шаг регистрации создаёт новый счёт (`billing.js` `issueVisitInvoice`
~:435-703, INSERT ~:630-651): мастер (~:2950), быстрая регистрация
(`walk-in-booking.js` ~:335), калькулятор (`service-picker-modal.js` ~:3217), направление
врача, окно визита (`visit-modal.js` ~:1188), счёт визита (`visit-bill.js` ~:347). В счёт
дописывает только `cashier_line_add` (~:1653-1667). На dev: 17 счетов созданы, пока
предыдущий счёт того же визита ещё не оплачен.

**Как будет.**
- `create_invoice_for_visit`: если у визита есть «редактируемый счёт пациента» —
  плательщика нет, `status = 'unpaid'`, `paid_amount = 0`, платежей (и возвратов) по нему
  никогда не было, своё здание, не госпитализация, не DEP-/CARD- — новые строки
  дописываются в него (то же правило, что у `cashier_line_add`, пересчёт
  `repriceUnpaidInvoice(absolute)`), ответ `{ invoice, appended: true }`. Иначе — новый
  счёт, как сейчас.
- Счета плательщику не сливаются никогда. Проверки «только врач» — по новым строкам.
  Ручная скидка новой части добавляется к скидке счёта; скидка уже выставленной части
  не меняется. `rest_discount` описывает новую часть (перенос скидки мастера работает).
- Все двери идут через эту же выборку; экран: «Добавлено в счёт № … — новая сумма …»,
  печать обновлённого счёта/маршрутного листа.
- Номера очереди выдаются при оплате, как сейчас.

**Тесты.** Второй вызов при неоплаченном первом — тот же счёт; не сливается с
плательщиком, частично оплаченным, долгом, отменённым, со счётом, по которому когда-либо
были платежи, с другим зданием и госпитализацией; оплата ставит в очередь все строки;
проверки врача — только по новым строкам; перенос скидки мастера не изменился; список
кассы — одна строка на счёт.

## U10a. Бонус врачу за направление — по строке (REFERRAL_LINE_V1)

## U11. Этикетка — на пробирку, номер не меняется (LAB_TUBE_LABEL_V1)

**Сегодня.** Штрих-код этикетки — номер одной строки анализа (`lab-doc.js` ~:389,
8 цифр); «Штрих-код» в карточке печатает ОДНУ этикетку на визит с `rows[0]`
(`laboratory.js` ~:1065), а строки идут по `id desc` (~:700/707) — это самая НОВАЯ
строка. На снимке владельца № 00000032 — «Анализ мочи» второго счёта; кровь с этим
номером прибор не находит («неоднозначно», две открытые «Анализ крови»). Время на
этикетке — UTC (`nowIso`, ~:86/1199/1312): 14:06 вместо 19:06. Нет тихой зоны у Code128
(`lab-barcode.js` ~:48/63/72). Номер счёта нигде не подставляется — ни пересылкой, ни
Easy-Med.

**Как будет.**
- «Штрих-код» в карточке печатает по этикетке на каждую пробирку: строки визита
  группируются по анализатору, который их ведёт (настройки приборов), иначе по
  материалу, иначе этикетка на строку. Номер этикетки — САМАЯ СТАРАЯ строка группы (не
  меняется, когда добавляют анализ). На этикетке — короткие названия анализов.
- Время на этикетке — местное.
- Тихая зона по краям штрих-кода.
- Просьба к лаборатории (через владельца): партия 2–3 пробирок на BC-780 — фото списка
  проб, строки `forwarder.log` за это время, фото настроек штрих-кода и LIS. По ним —
  отдельное решение, если BC-780 кладёт номер в другое поле.

**Тесты.** Номер этикетки не зависит от порядка выборки и от строк, добавленных позже;
случай со снимка (2 счёта × кровь+моча) — этикетка крови ведёт к строке крови; время
местное.
