# Журналы в «Отчётах»: журнал услуг и реестр стационарных пациентов (JOURNALS_V1) — дизайн

Метки: `JOURNALS_V1`, подметки `…_SERVICE`, `…_REGISTER`, `…_WARD_CLASS`, `…_PRINT`, `…_ACCESS`.

## Просьба владельца (2026-10-02)

Владелец показал три журнала из прежней программы:

- «Годовой отчет по пациентам» — реестр стационарных пациентов;
- «УЗИ стационар»;
- «ЭКГ журнал».

Его слова: журнал не должен быть «по услугам» (отдельный журнал на каждую услугу). Должен быть один журнал, где выбирают услуги из списка и тип — стационар или амбулатория.

## Решения владельца (2026-10-02)

| Вопрос | Решение |
|---|---|
| Какие журналы | «Service journal + register»: журнал услуг и реестр стационарных пациентов, оба в «Отчётах» |
| «Ким томонидан йўлланган» | «The sending doctor»: у пациента на койке — лечащий врач; у амбулаторного — врач, рекомендовавший услугу в своём кабинете, иначе источник направления визита или «сам» |
| «Йўллангандаги ташхис» | «Admission / doctor's dx»: у пациента на койке — диагноз при поступлении или последний клинический; у амбулаторного — подписанный диагноз направившего врача, если есть |
| Тип койки | «Add a ward class»: у палаты свой класс — Люкс / Полулюкс / Обычная |
| Какие строки | «Every paid service»: каждая выбранная услуга, оплаченная (или оказанная на койке) и не отменённая; заключение — если подписано, иначе пусто |
| Вывод | «Excel + Print»: Excel как сейчас и новая кнопка «Печать» |

Владелец согласился с дизайном целиком («yes … go ahead»).

**Заключение** пишется при подписи в окне врача (`service-workspace.js` `handleSignFinalize`):
- документ `visit_documents` (`doc_type` `diag` или `protocol`, `voided_at IS NULL`, `visit_service_id`); текст — `body.conclusion` / `body.description` (`diag`) или `dx` / `conclusionText` (`protocol`);
- черновик в `visit_services.notes`;
- поле `visits.conclusion`.

**Кто направил**
- `recommended_services.recommended_by` — рекомендация врача из кабинета.
- `visits.referral_source_id` → `referral_sources`.
- `admissions.attending_doctor_id`.

**Диагноз**
- `admissions.admission_diagnosis`.
- Последний опубликованный `admission_reviews.diagnosis`.
- Амбулаторно — только в `visit_services.notes` (`diagnoses[]`, `primary_diagnosis`) и в теле подписанного документа консультации.

**Класс палаты не хранится.** `beds.type` (`standard`/`icu`/`isolation`/`vip`/`recovery`/`observation`) и `wards.type` — не Люкс / Полулюкс / Обычная.

## 1. Журнал услуг (`JOURNALS_V1_SERVICE`)

Новый вид отчёта `service_journal` в `run_report`, новая карточка «Журнал услуг» в `REPORT_DEFS`.

### Параметры

- **Период** — как у всех отчётов.
- **Здания / филиалы** — как у всех отчётов.
  - `JOURNALS_V1_RJ1` (ревью п. 8): визит без филиала (`visits.branch_id IS NULL`) — свой филиал, а приехавший из соседнего здания без филиала — не свой (`OWN_BRANCH_OR('v.branch_id')`, как у прочих отчётов). Строка акта — всегда свой филиал (`OWN_BRANCH_SQL`).
- **Услуги** — новый тип опции `services`: окно выбора из списка услуг с поиском и галочками и кнопкой «Выбрать все найденные». Набрал «УЗИ» — отметились все найденные УЗИ.
  - Пусто — отчёт не строится, подсказка «Выберите услуги».
  - Выбор помнится у пользователя: в браузере, только как удобство.
  - Сервер получает `service_ids` — массив целых, не больше 2000. Неизвестные id отбрасываются.
- **Тип**: «Стационар» / «Амбулатория» / «Все» (опция `kind_of_care`: `inpatient` / `outpatient` / `all`), по умолчанию «Все».

### Какие строки

Одна строка — одна оказанная выбранная услуга.

- **Строка визита (`visit_services`)**: `service_id` выбран, дата визита в периоде, `status` — из явного списка «прошла кассу»: `queued`, `collected`, `in_progress`, `resulted`, `completed` (тот же список, что `LAB_RESULT_STATUSES` в `visit-status-guard.js`; если у не-лабораторных строк есть ещё статусы «после кассы» — сверить словарь статусов по миграциям и `billing.js` и добавить явно).
  - Это ровно «прошла кассу» (`added` → `queued` и дальше: billing.js).
  - `added` (не оплачено), `cancelled`, возврат и любые неизвестные статусы не показываются.
  - **Возврат** (`JOURNALS_V1_RJ1`, ревью п. 1). Касса счёт почти никогда не помечает `refunded`: полный возврат отменяет счёт (`refund_payment` → `closeFullyRefunded` → `voidInvoice`), возврат строкой (`refund_invoice_line`) отпускает строку со счёта. Строка остаётся `completed` без `invoice_item_id`. Признак возврата — отметка `pay_refund_releases` (`kind 'out'` у строки визита, `'in'` у строки акта) на невыставленной строке: то же правило (`NOT_RELEASED_SQL`), что у окна визита (`visit_refunded_lines`) и у выплаты врачу. Счёт со статусом `refunded` тоже исключается.
  - Известный край: обычная отмена неоплаченного счёта (например, страховой счёт отменён, а денег никто не платил) отметки не ставит — работа сделана, строка в журнале остаётся.
- **Строка случая (`admission_services`)**: `service_id` выбран, `performed_at` в периоде, строка не снята или не отменена (условие — как у отчётов по стационару, `isInpatientLine`).
  - `JOURNALS_V1_RJ1` (ревью п. 3): только ВЫПОЛНЕННАЯ строка — `performed_at IS NOT NULL`, как `IN_DONE_SQL` выплаты врачу; дата — местный день `performed_at`. Запланированная (`planned_at`, без отметки «Выполнено») — ещё не оказанная услуга, в журнал не входит; прежнее «иначе дата начисления» убрано. Период по `performed_at` читает индекс `idx_admission_services_performed`.
- **Стационар или амбулатория.**
  - Строка случая — всегда стационар.
  - Строка визита — стационар, если у пациента в этот местный день шла госпитализация: `admitted_at` не позже дня и `discharged_at` пусто или не раньше дня. Для таких строк берётся этот случай. Если случаев несколько — последний поступивший.
  - `JOURNALS_V1_RJ1` (ревью п. 7): выписан и снова положен в тот же день. Из случаев этого дня сначала берётся тот, в чьё время попадает строка: её `visit_services.scheduled_at`, иначе `visits.visit_date` (сравнение `julianday`). Не попала ни в один — правило дня, последний поступивший.
  - Иначе — амбулатория.
- **Без двойного счёта.** Если для одного пациента, одной услуги и одного дня есть и строка визита, и строка случая — показывается одна, строка визита: у неё есть заключение.
- **Сортировка**: дата, затем ФИО, затем услуга.

### Колонки

| Колонка | Откуда |
|---|---|
| № | порядковый номер строки |
| Ич. рақам (Пор. № пациента) | порядковый номер пациента в журнале: первый встреченный — 1, следующий другой — 2; у одного пациента в журнале один номер (как в прежнем «УЗИ стационар») |
| ФИО | `patients.full_name` |
| Пол | `patients.gender` словом |
| Год рождения | первые 4 знака `patients.date_of_birth` |
| ИБ № | `admissions.admission_no` случая — только у стационарных строк |
| Кто направил | см. ниже |
| Диагноз при направлении | см. ниже |
| Дата | местный день визита (строка визита) или `performed_at` (строка случая) |
| Услуга | `services.name` |
| Заключение | см. ниже |
| Врач | исполнитель: `visit_services.doctor_id`; у строки случая — `admission_services.performer_id`, иначе `doctor_id` |
| Лечащий врач | `admissions.attending_doctor_id` случая — только у стационарных строк |

Когда выбран тип «Амбулатория», колонок «ИБ №» и «Лечащий врач» нет.

### Кто направил

1. **Стационар** — лечащий врач случая. Если его нет — «Стационар».
2. **Амбулатория.** Сначала врач, рекомендовавший эту услугу этому пациенту в кабинете (`recommended_services.recommended_by` / `recommended_by_name`; та же услуга и пациент, рекомендация не позже дня визита — ближайшая по времени).
   - `JOURNALS_V1_RJ1` (ревью п. 5): рекомендация считается, только если она за 90 дней до дня визита (`REC_WINDOW_DAYS`) и не закрыта раньше него. Закрытие пишет `recommended_services.closed_at` вместе со статусом: окно визита при добавлении рекомендации в визит — `status = 'done'` (`visit-modal.js`), «Удалить» в кабинете — `'cancelled'` (`service-workspace.js`, `visit-modal.js`); открытая — `closed_at IS NULL` (как `referral-autofill.js`). Закрытая в день визита — закрыта этим визитом и считается. `cancelled` не считается никогда.
3. Если рекомендации нет — источник направления визита (`visits.referral_source_id` → имя источника).
4. Иначе «сам».

### Диагноз при направлении

1. **Стационар** — `admissions.admission_diagnosis`. Если пусто — последний опубликованный `admission_reviews.diagnosis`, как берёт реестр (`admissions-register.js:43-46`).
2. **Амбулатория** — диагноз подписанной консультации направившего врача: у того же пациента, тот же или более ранний день, не раньше 30 дней, врач = «кто направил», если это врач. Текст — из подписанного документа (основной диагноз «код — название», иначе `primary_diagnosis`).
3. Нет — пусто.

### Заключение (`JOURNALS_V1_CONCLUSION`, решение владельца 2026-10-02)

Слова владельца: «the fields of the "conclusion" in the journal → the "diagnosis" or "conclusion" in the doctors cabinet. if lab or any other leave blank or offer something». Из предложенного он выбрал «Status only». Правило заменяет прежнее (`body.conclusion` / `conclusionText` / `dx` / `description`).

По строке, по порядку:

1. **Подписанный документ врача.** Последний неотозванный `visit_documents` этой строки (`visit_service_id`, `doc_type IN ('diag','protocol')`, `voided_at IS NULL`). Сначала поле кабинета «Заключение», пустое — «Диагноз». Что пишет кабинет при подписи (`service-workspace.js` `handleSignFinalize` → `buildBlankData`, `_BLANK_FIELD_MAP`):
   - протокол приёма (`protocol`, снимок `buildBlankData`): раздел «Заключение» (`conclusion_text`) → `body.conclusionText`; раздел «Диагноз» (`primary_diagnosis`, иначе основной диагноз `_mainDxText`) → `body.dx`; все диагнозы с типами → `body.diagnoses`;
   - заключение исследования (`diag`): поле «Заключение» бланка исследования (`primary_diagnosis`) → `body.conclusion`; «Описание» (`instrumental_text`) → `body.description`.

   «Заключение» = `body.conclusionText`, у исследования `body.conclusion`. Пустое — «Диагноз»: основной из `body.diagnoses` «код — название», иначе `body.dx`. «Описание» исследования — находки, не заключение: не берётся. Документ без текста в этих полях — как нет документа.
2. **Анализ** (то же правило «анализ ли это», что у очереди лаборатории: `lab-service.js` `isLabService` — `type = 'lab'` / `is_lab`, отдел-лаборатория, вид услуги с «лабораторным» именем, привязанная активная панель) без документа: «Результаты выданы дд.мм.гггг» — местный день `visit_services.verified_at`, который ставит «Проверить и выдать»; не выдан — пусто (строка акта госпитализации выдачи не несёт — пусто).
3. **Любая другая услуга** без документа: «Выполнено», когда строка отмечена выполненной (строка визита — `status = 'completed'`, строка акта — `performed_at`).
4. Иначе — пусто.

**Документ врача** (`JOURNALS_V1_RJ1`, ревью п. 6). Реестр (`/api/db`) пускает писать `diag` / `protocol` и регистратуру, и медсестру. Журнал читает документ как врачебный, только если его автор (`created_by`) — врач этой строки (`visit_services.doctor_id`; исполнитель бывает и не врачом), пользователь с `is_doctor = 1` или администратор (роль `admin` или `admin` в `extra_roles`, как `isAdminUser`). Иначе документ для «Заключения» не существует. То же правило — у консультации направившего для «Диагноза при направлении».

**Документы до v3.12.0** (`JOURNALS_V1_RJ2`, F2). До 970cc91 (27.09) кабинет вставлял документ сам, и `created_by` у всех протоколов и заключений исследований того времени пуст. Но тело всегда несёт `meta.signedBy` (`DOC_AMEND_AUDIT_V1`, `handleSignFinalize` той версии — проверено по `970cc91^`). Документ без автора, но с `meta.signedBy` — подписанный в кабинете; без автора и без `meta.signedBy` (запись через `/api/db`) — не читается.

**Какой документ строки** (`JOURNALS_V1_RJ2`, F4, F5). Документ должен быть и этой строки (`visit_service_id`), и этого пациента (`visit_documents.patient_id = visits.patient_id` визита строки) — иначе он чужой. Из документов строки (новые сначала) берётся последний С ТЕКСТОМ «Заключения» или «Диагноза»: повторная подпись с пустыми полями не прячет прежний подписанный документ. Нет ни одного с текстом — статус строки (п. 2–4 правила выше).

Статус («Результаты выданы {date}», «Выполнено») переводится на языке экрана шаблоном `cells_t` (`[строка, колонка, шаблон, значения]`): колонка «Заключение» — не перечисление. Отчёт несёт четвёртое примечание с этим правилом.

Черновики не показываются. Длинный текст — целиком в Excel, на экране обрезается до 300 знаков.

### Права

Новая группа отчётов «Журналы» (`reports.journals`): `service_journal` и `inpatient_register`. Правила — как у прочих групп (`canSeeReportKey`): не настроенная роль — администратор и тот, у кого есть раздел «Отчёты».

Владелец доверил настройку ролей: группа добавляется в «Роли» с понятной подписью. Журналы содержат диагнозы, заключения, паспорта и оплаты.

**Миграция 235** (`JOURNALS_V1_ACCESS`, доработка `JOURNALS_V1_RJ1`, ревью п. 2):
- штатному `head_doctor` — «Журналы: Просмотр» (раздела «Отчёты» у него нет; ставится первым);
- ЛЮБОЙ строке `role_permissions` — штатной и своей роли клиники, — у которой группы отчётов уже настроены (в правах есть хоть один ключ `reports.…`, тот же признак, что у миграции 179), — «Журналы: Нет». Иначе новая группа открылась бы сама копии кассира, роли «только Касса», копии склада, оператору колл-центра (152). Штатные кассир и склад попадают сюда же;
- роль без единого ключа `reports.…` — прежнее правило групп (администратор и раздел «Отчёты»);
- записанный `reports.journals` не перезаписывается; повторный накат ничего не меняет.

**Правило в коде** (`JOURNALS_V1_RJ2`, финальное ревью F1). Запись миграции живёт, пока права роли не перепишут без ключа: справочник главной клиники старой версии затирает `role_permissions` филиала (`branch-sync/catalogue.js`, без проверки версии), устаревшая вкладка «Роли» сохраняет матрицу без новой строки. Поэтому для ОДНОГО ключа `reports.journals`: если хоть одна роль человека настроена (есть ключ `reports.…`) и ни одна не записала «Журналы» — «Нет». Прежнее правило (администратор, раздел «Отчёты») — только когда ни у одной роли нет ни одного ключа `reports.…`. Прочие группы не меняются. Одно правило в трёх местах: сервер (`report-access.js` `canSeeReportKey`), оболочка (`permissions.js` `reportGroupAllowed`) и стандарт экрана «Роли» (`gate-fallbacks.js` `fallbackLevel` — иначе экран показал бы «Просмотр» и записал его при сохранении). Совпадение сервера и оболочки закреплено матрицей ролей (`journals-access-parity.test.mjs`).

**Явная выдача «Журналов» одной роли** (`JOURNALS_V1_RJ2`, F3). Главный врач — врач с надстройкой «Главный врач». Закрой клиника «Отчёты» роли «Врач» — самый щедрый уровень раздела по ролям «Нет» (у надстройки раздела нет), и закрытый раздел запирал выданные журналы. Теперь роль, которая САМА записала `reports.journals` не ниже «Просмотр» и сама `reports` не закрыла, открывает журналы — как бы ни стоял раздел у других ролей человека; хаб «Отчётов» (пункт меню и маршрут) открывается с одними плитками журналов. Прочие группы это не открывает. Роль, закрывшая «Отчёты» сама, свои «Журналы» не открывает (закрытый раздел закрывает то, что в нём). Сервер (`journalsGrantedByRole`) и оболочка (`reportGroupAllowed`, права каждой роли — `_roleGrants`) — одно правило.

## 2. Реестр стационарных пациентов (`JOURNALS_V1_REGISTER`)

Новый вид отчёта `inpatient_register` в `run_report`, карточка «Реестр стационарных пациентов».

### Строки и сортировка

- **Строки**: случаи, у которых `admitted_at` (местный день) в периоде; случаи без поступления (`ordered`) — нет.
- **Здания**: фильтр как у отчётов по стационару.
- **Сортировка**: дата поступления, затем ИБ №.

### Колонки

| Колонка | Откуда |
|---|---|
| ИБ № | `admission_no`, иначе `#id` |
| ФИО | `patients.full_name` |
| Год рождения | первые 4 знака `patients.date_of_birth` |
| Отделение | как `deptText` реестра: `admissions.department`, иначе отделение палаты |
| Дата рег | местный день `admitted_at` |
| Дата выписки | местный день `discharged_at` |
| ФИО ЛВ | лечащий врач |
| Сумма оплаты | сумма `invoices.paid_amount` счетов случая (`invoices.admission_id`), кроме `void`/`refunded` — как `paid_total` в `admissions_register` |
| Тип палаты | класс палаты случая (п. 3) |
| Дата оплаты | местный день последней оплаты по счетам случая (`payments.paid_at`), иначе пусто; платёж, возвращённый целиком (строки `REFUND#<платёж>`, как `refundedOfPayment`), — не оплата (`JOURNALS_V1_RJ1`, ревью п. 10a) |
| Страна | `patients.country` |
| Регион | `patients.region` |
| Адрес | `patients.district`, `patients.address` через запятую, как в реестре |
| Паспорт | `patients.passport_number`, иначе `national_id` |
| Телефон | `patients.phone` |

**Итог**: «Сумма оплаты» суммируется (итоговая строка, как у прочих отчётов).

Вкладка «Госпитализации» остаётся как есть: отчёт — отдельный вид с периодом. Чтобы правило «сумма оплаты» жило в одном месте, считающая функция выносится и используется обоими.

## 3. Класс палаты (`JOURNALS_V1_WARD_CLASS`)

**Миграция 234**: `ALTER TABLE wards ADD COLUMN ward_class TEXT CHECK (ward_class IN ('lux','semi_lux','standard'))` — без значения по умолчанию, пусто = не задано. Только `ADD COLUMN`: таблица не перестраивается (урок 1.1.0).

**Экран.**
- В настройках палаты — выбор «Класс палаты»: Люкс / Полулюкс / Обычная / не задан; ru/uz/en: «Lyuks / Yarim lyuks / Oddiy», «Lux / Semi-lux / Standard».
- Найти, где редактируется палата: `ward-beds.js` или настройки стационара.
- Право — то же, что у правки палаты.

**Реестр.**
- Класс палаты, где сейчас (или при выписке) стоит койка случая: `admissions.bed_id` → `beds.ward_id` → `wards.ward_class`.
- Нет койки или класса — пусто.
- Переводы (`admission_transfers`) не разбираются: берётся текущая или последняя койка. Так и сказано в подсказке колонки.

**Синхронизация зданий**: если `wards` ездит между зданиями, `ward_class` добавляется к отправляемым колонкам — проверить `SHIPPED` / каталог branch-sync.

## 4. Печать (`JOURNALS_V1_PRINT`)

В конструкторе отчёта рядом со «Скачать Excel» — кнопка «Печать». Она работает для любого отчёта.

- Открывает новое окно со страницей для печати:
  - заголовок отчёта;
  - строка «Период: дд.мм.гггг — дд.мм.гггг», здания, если выбраны;
  - таблица: ВСЕ строки, не только 300 предпросмотра;
  - итоговая строка, если есть.
- Затем `window.print()`, как `kitchen-sheet.js` и `procurement.js`.
- Альбомная ориентация, если колонок больше 8.
- Шрифт печати — исключение из шкалы шрифтов (`type-scale-exempt`, PRINT).
- Строки берутся из уже полученного ответа `run_report` — второго запроса нет.
- Тексты — экранированные, без вставки HTML из данных.

## 5. Что НЕ делаем

- **Word** — владелец выбрал Excel и Печать.
- **Сохранённые именованные журналы** («УЗИ стационар» как пресет) — вместо них «Выбрать все найденные» и запомненный выбор.
- **Связь визита со случаем в базе.** Стационар определяется по дню госпитализации, как в лаборатории.
- **Разбор переводов** между палатами для класса палаты.

## 6. Тесты

**Сервер**

`service_journal`:
- строки визита оплаченные (`queued` / `completed`) показаны; `added` и `cancelled` — нет;
- стационар по дню госпитализации, включая день поступления, день выписки и незакрытый случай; амбулатория — вне госпитализации;
- строка случая — всегда стационар;
- без двойного счёта визит + случай;
- Ич. рақам: у одного пациента один номер, номера по порядку;
- «кто направил» — по цепочке: лечащий, рекомендация (ближайшая не позже дня), источник, «сам»;
- диагноз — по цепочке: `admission_diagnosis`, последний опубликованный review, подписанная консультация направившего;
- заключение — только подписанное, отозванное не берётся; «Заключение» кабинета, иначе «Диагноз», описание — нет; без документа — «Результаты выданы дд.мм.гггг» у анализа, «Выполнено» у прочего, шаблоном `cells_t` (`JOURNALS_V1_CONCLUSION`);
- фильтр «Амбулатория» убирает две колонки;
- `service_ids`: пустой → отказ с подсказкой; мусор отброшен; больше 2000 → отказ.

`inpatient_register`:
- период по `admitted_at`;
- сумма оплаты без `void`/`refunded`;
- дата последней оплаты;
- класс палаты;
- `#id` без номера.

Права:
- группа `reports.journals`: без настройки — админ и раздел «Отчёты»; с настройкой — по ключу;
- карточка ↔ группа (`reports-hub-v2.test.mjs`).

Миграция 234:
- только `ADD COLUMN`;
- CHECK;
- повторный накат.

**Клиент**
- окно выбора услуг: поиск, «Выбрать все найденные», запомненный выбор, пустой выбор;
- колонка «Тип палаты» и выбор класса в настройках палаты;
- «Печать»: строит страницу из ответа, все строки, экранирование.
- Переводы: ru/uz/en, проверки покрытия, качества узбекского и шкалы шрифтов зелёные.

**Сквозная проверка** — на копии dev через `createApp`:
- оба отчёта строятся, печать открывается;
- Excel сохраняется;
- без ошибок в браузере.
